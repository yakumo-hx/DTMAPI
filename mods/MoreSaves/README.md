# DTMAPI 更多存档

当前源码版本为 1.1.4，需要 DTMAPI Runtime 0.7.5。打开存档页或翻页时，只为当前页读取存档摘要；世界数据仍检查 JSON 结构，但不创建整份对象树。来回翻页或重新打开界面时，文件未变化的摘要直接复用；文件变化或此前读取失败时重新读取。解密和最低存档版本检查沿用游戏规则。读取失败的已有存档显示为不可用。

- Official enablement owns 60 native slots, displayed through five pages of twelve original cards (three columns, four rows). Bottom-right controls show the current page and disable at the first/last page.
- The panel keeps local cell indices 0–11; the native selected target is `page * 12 + cell`, displayed as #1–#60. Page changes preserve the local cell and refresh only twelve summaries. No per-frame archive scan is installed.
- Confirmation binds the selected native path, file attributes and UI selection. Page/slot changes, closing the panel or changed file attributes invalidate pending confirmation. These observations do not identify deliberate content replacements that preserve length and modification time. Once accepted, native LoadingPanel/DelayFrame owns a one-shot fixed request that survives the normal panel close; owner removal, a newer opening/start or changed file attributes reject it.
- Existing files with unreadable summaries are unavailable, not empty. Native new/load and ModChangeList entrypoints retain their roles. Copy chooses the lowest genuinely absent current file among 60 slots, and refuses unreadable existing slots with their slot number. It reads the selected disk source without loading or saving a game.
- Copy uses native decoding/FixArchiveIndex/encoding and verifies that only the top-level and baseData archiveIndex changed. Numbers are compared by value, because the native writer may print the same number with more digits. Unknown values and opaque MES strings must survive; inputs the native codec cannot preserve are rejected. A same-directory CreateNew temporary is checked and moved without overwriting a destination, including one that appears after the initial check. Only a verified committed copy changes the selected page; a failure after commit reports its fixed slot as unconfirmed and leaves the copy intact.
- Delete uses the native inner bool result and requires current to disappear with matching length/mtime in the same-slot .bak before refreshing to empty. The native policy may remove an older .bak even when deletion then fails; failed or uncertain operations retain the card and report that distinction. Prev files, other slots and sidecars are not copied or deleted.
- Rename adds a name field and explicit button to the left of the original three buttons. Typing, Enter, blur and navigation do not commit; changing slot/page or closing clears the draft. Only a selected readable current can be renamed, with the native name length and default-name representation. The product changes the two stored name strings, checks all other values, then uses the native temporary/previous rotation and atomic replacement policy. A committed but unconfirmed result stays on disk and is reported; it is never blindly rolled back or submitted again. No live gameplay state is loaded or saved to rename a file. The full new-game matrix and cloud/vanilla composition remain separate gates.
- Copy, delete and rename do not compute archive content hashes or cache validity. Field-preservation checks still compare the actual decoded copy/rename documents; backup bytes are covered by focused file-operation tests. If a move/replace consumes its temporary and then throws, the fixed target is reported as unconfirmed without retry or rollback.
- The pre-1.00 filename migration still handles only indices 6–11 and their current/prev/bak roles. File.Move success removes the source; existing destinations preserve the source without overwriting. No archive content is rewritten by migration.
- Official disable restores native six-slot capacity, removes this product's nine GameDataUiState hooks and paging controls, and rebuilds an open native panel. Extra native archive files are preserved. The Frozen ISaveSlotsApi and its mutually exclusive owner remain unchanged.
- Missing manager retries retain the existing bounded 750 ms cadence. An incomplete final capacity restoration retains the exact owner until explicit cleanup succeeds.
