# DTMAPI 0.5.0-alpha Release Hygiene Report

Date: 2026-06-11

Status: release-preparation record for the Developer Preview branch.

## Release Position

DTMAPI `0.5.0-alpha` is prepared as a new Workshop release batch:

- New DTMAPI Runtime / Installer item.
- New DTMAPI feature mod items.
- No in-place overwrite of old DLK/SMAPI Workshop items.
- Player-facing mod text can say the selected mods are stable for normal play, while technical docs continue to mark the runtime as Developer Preview and GameBridge APIs as Experimental.

## Recommended Player Migration

The safest path is:

```text
uninstall old DolocTown SMAPI runtime
unsubscribe or disable old DLK mods
restart Steam and Doloc Town
install DTMAPI Runtime
subscribe to new DTMAPI mods
check DTMAPI Settings -> Status/Mods/Logs
```

This avoids mixed hook owners and stale code DLL state. It also avoids relying on old SMAPI uninstallers to clean local mod folders that they did not own.

## Old Content Handling

DTMAPI detects old SMAPI/DLK paths and records them in `install-state.json`. It does not delete Steam Workshop cache. Local old packages are either left in place for guidance or moved only through explicit legacy-migration backup paths.

Observed local state during dry run:

- Steam Workshop unsubscribe can remove the old mod from the in-game enabled list after Steam/game restart, but it does not guarantee that every manually copied or previously migrated local folder is gone.
- The local `MODS/DLK_*` folders are still detectable and should be treated as legacy local packages, not as active proof of Workshop subscription.
- Known old Workshop cache IDs can remain detectable on disk; the DTMAPI installer records them but never deletes Workshop content.
- The safest player-facing migration remains uninstall old SMAPI, unsubscribe/disable old DLK mods, restart Steam and game, install DTMAPI, subscribe to new DTMAPI mods, then check Manager Status/Logs.

## Release Manifest Schema

`DTMAPI/release-manifest.json` is generated as UTF-8 no BOM JSON and records:

- `DTMAPIVersion`
- `BinaryVersion`
- `BuildCommit`
- `BuildTime`
- `PackageKind`
- `SupportedGameVersion`
- `MinimumGameVersion`
- `IncludedAssemblies`
- `BundledMods`
- `ExperimentalApiNotice`

## Install State Schema

`DTMAPI/install-state.json` is generated as UTF-8 no BOM JSON and records:

- `InstalledAt`
- `DTMAPIVersion`
- `BinaryVersion`
- `SourceRepoCommit`
- `GameDir`
- `PluginDir`
- `FilesInstalled`
- `BepInExDetectedBeforeInstall`
- `BepInExInstalledByDTMAPI`
- `BackupsCreated`
- `LegacyModsDetected`
- `LegacyModsMoved`
- `InstallScriptVersion`
- `Release`

The file intentionally avoids Steam account identifiers and other player-private information.

## Uninstall State Schema

`DTMAPI/uninstall-state-YYYYMMDD-HHMMSS.json` is generated during uninstall and records:

- `UninstalledAt`
- `DryRun`
- `GameDir`
- `BackupDir`
- `FilesPlanned`
- `FilesRemoved`
- `FilesBackedUp`
- `FilesSkipped`
- `KeepReports`
- `KeepConfigs`
- `KeepBackups`
- `RemoveBepInEx`
- `BepInExRemovalAllowed`
- `Errors`

Default uninstall keeps player Mods, Steam Workshop content, reports, configs, backups, and BepInEx core. `-RemoveBepInEx` only becomes active when `install-state.json` says DTMAPI installed BepInEx and the user explicitly opts in.
