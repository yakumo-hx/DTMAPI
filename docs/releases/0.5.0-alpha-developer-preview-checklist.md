# DTMAPI 0.5.0-alpha Developer Preview Checklist

Status: draft checklist for Refactor.

Date: 2026-06-11

This checklist is for a Developer Preview package. It is not a Stable release gate and does not promote Experimental or Diagnostic APIs.

## Required Validation

- `git diff --check` passes on the release candidate.
- `tools/scripts/build.ps1 -Configuration Release` passes.
- `tools/scripts/test.ps1 -Configuration Release` passes.
- The game install path is prepared by `tools/scripts/install-to-game.ps1` or the current package script without hard-coded local paths.
- DirectExe Manager MVP smoke passes with Status, Mods, Errors, Hooks, Features, Logs, Logs export, Status/Logs screenshots, and `ManagerStatusSummaryCopy`.
- DirectExe HookProbe smoke passes on local save slot 3 / index 2.
- Exit checks show no leftover `DolocTown.exe` and no fatal instance popup.

## Install-To-Game Gate

- BepInEx bootstrap installs only the DTMAPI bootstrap under `BepInEx/plugins`.
- Ordinary DTMAPI mods are installed through the supported game `Mods` / official-local route, not under `BepInEx/plugins`.
- DTMAPI dependency normalization accepts the current `0.5.0-alpha` API baseline while BepInEx metadata remains numeric.
- `tools/scripts/install-to-game.ps1 -DryRun` prints the planned install state and does not build, copy, move, or delete files.
- A normal install writes UTF-8 no BOM `DTMAPI/release-manifest.json` and `DTMAPI/install-state.json`.
- `install-state.json` records version, binary version, source commit when available, game/plugin paths, installed files, BepInEx detection/installation state, backups, legacy movements, and legacy detections without Steam account data.
- The runtime Workshop package includes `1_install_dtmapi.bat`, `2_uninstall_dtmapi.bat`, and `3_check_dtmapi_status.bat`.
- Install output excludes `bin`, `obj`, `.tools`, PDB files, report zips, evidence payloads, official DLLs, and decompiled source.

## Uninstall / Migration Gate

- `tools/scripts/uninstall-dtmapi.ps1 -DryRun` prints planned backup/removal work without moving files.
- Default uninstall backs up and removes only DTMAPI-owned runtime files and helper scripts.
- Default uninstall keeps player `Mods/`, Steam Workshop content, `DTMAPI/reports`, `DTMAPI/config`, `DTMAPI/backups`, and `BepInEx/core`.
- `-RemoveBepInEx` is allowed only when requested and when `install-state.json` proves BepInEx was installed by the DTMAPI installer.
- Legacy SMAPI/DLK paths are detected and recorded. Workshop cache is never deleted by DTMAPI.

## Sample Mods Gate

- Development-only sample/test mods are not included in a normal player install unless an explicit test/smoke flag requests them.
- HookProbe remains test-only and must not be left enabled in a normal player package.
- Migrated local mods used for smoke evidence should load through the same dependency/version path ordinary mods use.
- Release Workshop staging for the first player batch is limited to DTMAPI Runtime plus the eight selected feature mods: Zoom, ActionSpeed, OneActionComplete, ChestLocatorEnhancer, YKeyConsole, FishBreedingAssistant, MoreSaves, and AnimalHusbandryProgress.

## Manager UI Gate

- Status shows overall status, mod counts, diagnostics counts, failed/missing hook counts, failed/degraded feature counts, refresh state, report state, latest log state, and latest report path state.
- Status Refresh reports `refreshed` or `manager refresh failed` based on `LastManagerRefreshError`.
- Status Copy Summary either copies the support text or reports `copy-unavailable` and writes the same summary to the runtime log.
- Mods, Errors/Warnings, Hooks, and Features show `showing first N of total` and keep row text truncated.
- Features remains read-only and does not expose the internal Manager view model as a public mod API.
- Logs shows export status, exported report path, snapshot latest report path, path match state, snapshot report status, and export failure text.
- The title DTMAPI button still opens Config first; Manager pages do not change Config save/reset/cancel/keybind behavior.

## Report Export Gate

- Logs Export Report calls the existing diagnostics export path.
- The returned export path matches the refreshed snapshot `LatestReportPath`.
- `latest-report.txt` is fresh for the current evidence when a smoke run claims report-export proof.
- Compact web packages may omit oversized report zip payloads, but must say what was omitted.

## Known Experimental APIs

- `ICameraViewApi` remains Experimental and still requires manual CameraView QA confirmation before promotion.
- `IFishingAutomationApi` remains Experimental; option normalization and native-owner boundaries are documented but not stable.
- `ISaveSlotsApi` remains Experimental; slot 7+ lifecycle, delete/copy/restart recognition, and broader layout evidence remain pending.
- Gameplay/content APIs that still depend on GameBridge/native hooks remain Experimental unless the public API matrix explicitly says otherwise.
- `IDtmDiagnosticsApi` and Manager UI support rows remain Diagnostic/internal product surfaces, not stable gameplay APIs.

## Known Non-Goals

- No Workshop enable/disable writes.
- No full Manager visual redesign.
- No row detail panel or selected-row copy.
- No fallback ImGui overlay rewrite.
- No Stable or StableCandidate promotion caused by Manager UI evidence alone.
- No public API additions for Manager view-model, Copy Summary, or report state.

## Release Blockers

- Any failed build, unit test, Manager MVP smoke, HookProbe smoke, process exit check, or fatal popup check.
- Any stale `latest-report.txt` used as current evidence.
- Any public API change without API matrix review and update record.
- Any ordinary mod installed under `BepInEx/plugins`.
- Any packaged DLL/EXE/PDB/report/evidence/official/decompiled payload that violates the share/package boundary.
