This directory is the long-lived index for DTMAPI native-owner discovery by gameplay/content domain. It maps fuzzy author-facing goals to Doloc Town native responsibility functions and state holders before any GameBridge or public API rebuild starts.

This library is not a stability promotion record. It does not add public APIs, does not mark APIs stable, and does not prove runtime behavior without later implementation and game evidence.

The current 24456188 reference has the full player snapshot, AssetRipper export, and ILSpy output. The checked-in Native Function Map data was not regenerated by the baseline capture and remains historical; use the exact 24456188 decompiled symbol/body for task decisions or deliberately regenerate that workbench before citing current-build aggregate counts.

## Rules

- Start future API rebuilds from the relevant report here, then read the task-specific reverse maps and method bodies.
- Treat the per-report `Reverse baseline` headers as historical authoring context. Before implementation, re-open the named symbols in the current reverse reference.
- Do not expose raw decompiled, Unity, Harmony, or BepInEx types in `DTMAPI.Abstractions`.
- Treat official Workshop docs as content/beauty support evidence only, not proof that DTMAPI can mutate runtime state safely.
- Mark missing native owners as blockers. Do not patch ordinary mods to imitate a stable API.
- Runtime work still needs the [`PROJECT.md`](../../../../PROJECT.md) physical-owner classification, the authoritative domain save fixture, clean-exit checks, and public API matrix updates when a public contract changes. SharedNative/public adapters use GameBridge. G2 proves ProductNative packaging/lifecycle only for its synthetic fixture; the [Batch 6 identity contract](../../../architecture/batch6-managed-mod-identity-contract.md) alone owns the exact admitted real-product set and blocks every product beyond it. ContentOwner uses an optional Content Host and remains G7-blocked.

## Next-Use Pattern

When starting implementation from this library:

1. Pick one domain report and one narrow API boundary.
2. Re-open the exact reverse maps and decompiled classes named by that report.
3. Decide both API status (`stable open`, `experimental open`, `debug-only`, `registry-only`, `DTMAPI-internal`, or `blocked-rebuild`) and physical ownership (`Platform`, `SharedNative`, `ProductNative`, or `ContentOwner`). Visibility does not decide ownership.
4. Create or update one task-specific `docs/updates/YYYY/...` record with the chosen boundary, blockers, and validation requirements.
5. Update `docs/api/public-api-matrix.md`, `docs/debug/regressions/smoke-matrix.md`, hook/debug records, and `docs/updates` only after implementation evidence exists.
