# Evidence Retention Protocol

Use this protocol before pruning local files under `docs/debug/evidence/`.

## Canonical Allowlist

`docs/debug/evidence-retention-allowlist.json` is generated by:

```powershell
tools/scripts/build-evidence-retention-allowlist.ps1
```

It scans Git-tracked and otherwise unignored Markdown plus the authoritative `tools/release/dtmapi-product-catalog.json` and records:

- GAME-SMOKE run identities whose run-level logs/results are referenced;
- specifically referenced files or subdirectories within GAME-SMOKE;
- formal outer-run aggregates copied into a referenced final GAME-SMOKE root,
  including the MoreEquipmentSlots three-process cold-recovery receipt;
- canonical `DTMAPI-evidence/<case>/<timestamp>/...` identities independent of duplicated outer snapshots;
- referenced process-dump identities;
- first-level `BATCH5-GC-LADDER/<run>`, `BATCH5-NO-DEMAND/<run>`, `BATCH6-AUTOFISHING-MANAGER-LIFECYCLE/<run>`, `BATCH6-AUTOFISHING-BEHAVIOR-MATRIX/<run>`, `BATCH6-AUTOFISHING-GC-LADDER/<run>`, `PRERELEASE-ACTIVE-GC/<run>`, `CANDIDATE11/<transaction>`, and `WORKSHOP-SUBSCRIPTION-AUDIT/<run>` roots, including Workshop run names that contain spaces;
- all source files containing evidence references, plus the exact subset containing durable-root references.

Schema 5 makes those eight durable categories explicit. `test-runtime-evidence-retention.ps1` freezes the accepted Batch 5, Batch 6 AutoFishing and pre-release active-GC root sets, the terminal/interrupted smoke identities named by the final audit, and the durable-root source-file set including the Catalog JSON, so removing or silently reclassifying formal evidence fails normal validation until the contract is reviewed and regenerated.

An outer runner does not gain a new durable-root category merely because it
coordinates several GAME-SMOKE children. When the aggregate is release
evidence, the runner must copy its completed receipt into the final referenced
GAME-SMOKE root and documentation must link that exact artifact. The ordinary
`gameSmokeArtifacts` preservation path then owns it together with the child
run; an unlisted sibling outer directory is not protected by implication.

Run `tools/scripts/build-evidence-retention-allowlist.ps1 -Check` before cleanup and in normal repository validation. Placeholder or wildcard run roots such as `GAME-SMOKE/<id>` and `BATCH5-GC-LADDER/<run-id>` are intentionally excluded. Durable-root references are normalized to forward slashes and their first-level run identity; empty, rooted, or `.`/`..` segments anywhere in the reference, and invalid-filename run identities, fail generation instead of creating an unsafe preservation entry.

## Cleanup Boundary

The allowlist is a preservation input, not deletion authorization.

Before removing duplicated `DTMAPI-evidence` trees:

1. preserve run-level files for every listed GAME-SMOKE run;
2. preserve every listed GAME-SMOKE artifact and report ZIP;
3. materialize and hash one canonical copy of every listed runtime-evidence identity;
4. rewrite or validate tracked links against that canonical location;
5. treat process dumps separately because one file can consume multiple GiB;
6. preserve every listed Batch 5 ladder, no-demand run, Batch 6 AutoFishing Manager lifecycle, behavior matrix, GC ladder, pre-release active-GC run, Candidate11 transaction, and Workshop subscription-audit root as one indivisible evidence tree;
7. produce a dry-run byte/file manifest and obtain explicit deletion approval.

The tracked duplicate-evidence cleanup consumer requires schema 5, resolves every durable identity inside `docs/debug/evidence`, rejects missing or reparse-point roots, and fingerprints every file before and after an approved cleanup. A changed identity set, file count, byte count, or complete file-manifest SHA-256 blocks/aborts cleanup; the allowlist remains preservation input, never deletion authority.

Untracked chat references, external reports, and files never mentioned by project Markdown are outside the generated source scope. Add required evidence to durable documentation or a reviewed manual override before cleanup.

## Routine Collection Boundary

Routine GAME-SMOKE supplies its UTC start time to `collect-logs.ps1`. The collector inspects only immediate `case/timestamp` runtime directories created or updated since that boundary and preflights the selected batch before copying.

Default limits are:

- 128 selected runtime directories;
- 2,000 files;
- 512 MiB total;
- 128 MiB per file.

Exceeding any limit rejects the whole runtime-evidence batch and writes `DTMAPI-evidence-selection.txt`. The explicit `-IncludeRuntimeEvidence` full-tree mode remains exceptional and must not be used by routine GAME-SMOKE.

## Process Dump Boundary

Fatal-window process dumps are opt-in and use the separate lifecycle in [test-artifact-retention.md](test-artifact-retention.md). A captured dump is formal evidence only after source/destination length and SHA-256 match and a sibling `process-dump-receipt.json` records the handoff. Its `%TEMP%\DTMAPI-Dumps\<run-id>` source is disposable after that verified handoff.

The generated allowlist preserves Markdown-referenced `Process-Dumps` identities but is not deletion authority. Identical hashes or a common reviewed crash signature may nominate one canonical dump; removal of the other formal copies still requires a dry-run manifest and explicit approval. Missing debugger analysis lowers the value of repeated copies but does not by itself authorize deletion.
