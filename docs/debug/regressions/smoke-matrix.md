## Write Rules

- Add a row only when the game or runtime harness actually ran.
- Source builds, unit tests, parser checks, and architecture scans belong in the Update record, not this matrix.
- Keep one concise row per acceptance boundary. Put attempts, counters, and interpretation in the issue or Update record.
- Never replace user manual QA with smoke evidence.
- Preserve failed evidence; mark it superseded only when a later valid row owns the same acceptance boundary.
