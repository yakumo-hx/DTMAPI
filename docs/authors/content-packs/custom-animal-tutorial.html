综合案例：新增养殖动物

2026年10月27日 Yuuka

给牧场添一位新住户。用JSON定义灵魂、PNG定义形体、WAV定义声音。是的，并不限制是动物：你可以大胆发挥想象力。

一、整体说明

基于DTMAPI 0.7.5的畜牧内容包面向更熟悉官方mod内容的作者。目前的动物行为主要使用游戏内的四种动物，所以飞的、游的，暂时还不行。但官方的json系统已经支持较为全面的自定义能力。

准备用途
安装DTMAPI 0.7.5 及以上版本提供畜牧与音频模块，必选
本文提到的 9 份 JSON配置动物、物品、商店和资源关系，部分非必选
45 张动画 PNG + 1 张蛋图标沿用当前哈奇示例的帧清单，其他模板数量不同
2 段 WAV幼体、成年各一段叫声，没有的话会回退动物原声
icon.png、preview.png模组图标与预览图，给steam和游戏内mod界面显示

黄色内容只是标出了一些必改的内容。注释说明字段和值的含义、你可以做哪些修改，除了部分严格的规范，其他一切由你发挥。

每块 JSON 都是一个完整文件。点击“复制 JSON”后，按上方的路径保存为.json文件即可。复制按钮取得纯 JSON，标点也一起打包带走，注释不会，因为json不太支持注释。

二、文件结构

示例包的文件夹名为 DTMAPI_AnimalPack。你可以自定文件夹名，并将整个包放入官方本地模组目录。Windows 可将下面的路径粘贴到资源管理器地址栏：

%USERPROFILE%\AppData\LocalLow\RedSawGames\DolocTown\MODS
DTMAPI_AnimalPack/
├─ info.json
├─ manifest.json
├─ icon.png
├─ preview.png
├─ Content/
│  ├─ animal_tbanimal.json
│  ├─ animal_tbanimaldocument.json
│  ├─ item_tbitem.json
│  ├─ item_tbitemspawn.json
│  ├─ mod_tbmodstoreextension.json
│  └─ Sprites/
│     ├─ hatch_frame_manifest.json
│     ├─ icon_item_hatch_egg.png
│     └─ anim_animal_hatch_*.png   ← 45 张独立帧
└─ PackData/
   ├─ content.json
   └─ audio/
      ├─ hatch_pet_young.wav
      └─ hatch_pet_adult.wav

Content/ 放游戏原生数据和图片；PackData/content.json 集中写 DTMAPI 的动物定义与声音。资源路径从 DTMAPI_AnimalPack/ 这一层开始计算。

标有“DTMAPI 专属”的文件由 DTMAPI 读取；动物表中的 DTMAPI 动画键也已单独注明。帧清单标为“DTMAPI 配套清单”，供作者整理与核对资源。

2.manifest.json

DTMAPI 专属。放在包根目录，与 info.json 并排。本例保留真实的 DTMAPI.AnimalPack，制作自己的模组时按注释修改。

DTMAPI 专属manifest.json
{
  "UniqueID": "DTMAPI.AnimalPack",
  "MinimumDTMApiVersion": "0.7.5",
  "Type": "ContentPack",
  "Dependencies": [],
  "ManifestVersion": 2
}

ManifestVersion 选择 DTMAPI 清单格式。本例填写 2，名称、作者、说明和模组版本由根目录 info.json 提供；MinimumDTMApiVersion 则填写加载这个模组所需的最低 DTMAPI 版本。

畜牧、音频模块随 Runtime 提供，内容文件会自动建立模块使用关系。照着本例填写即可。

ID 怎么命名？

建议使用小写英文字母、数字和下划线。这里的 hatch 是物种 ID，你可以按自己的作品命名：

物种 ID 示例说明
hatch1可以，字母加数字。
hatch_hatch可以，用下划线分隔单词。
Hatch建议统一写成小写 hatch，所有引用保持相同拼写。

DTMAPI 的物种和动画机键冲突检查忽略大小写，部分原生表查询又区分大小写。整套配置统一小写最省事。改物种 ID 时，同步修改动物表、图鉴、动物袋的 preset_animal、DTMAPI 的 speciesId 和特殊照料表中的引用。

3. WAV：给它一个自己的声音

准备两段简短叫声，保存为 PCM WAV，并按文件树放入 PackData/audio/。推荐先剪掉首尾长静音，抚摸时就能听到干脆的回应。

volumeDb 控制音量；0 保持素材原音量，-6 可降低音量。先让它正常叫，再决定它有多爱聊天。

想先完成无自定义叫声的版本时，从第 8 步完整删除 audio 分区和 animals.voices 数组，保留 schemaVersion 与 animals.definitions。

五、游戏内验证

  1. 保存所用的 JSON，按帧清单放好 PNG；使用自定义声音时放好两段 WAV。
  2. 从 Steam 启动游戏，在“模组”界面启用“缺氧动物包”，按界面提示完成重启。
  3. 进入用于测试的存档，打开凯涅尼木的小动物商店，购买“麻袋（哈奇）”。
  4. 在有空余容量的畜棚放出幼体，观察待机、移动、吃饭和转向，抚摸时听叫声。
  5. 成长后检查成年外观、成年叫声和跳跃，夜间检查睡眠与醒来。
  6. 准备鸡窝和饲料，照料到满足产物条件后，检查是否获得哈奇蛋；在图鉴中查看动物与产物。

第一次先看“能加载、能放出、能走动”。再逐项确认成长、睡眠、声音和产物，定位问题会轻松很多。

遇到的现象先检查这里
模组列表里没出现DTMAPI_AnimalPack/info.json 是否位于这一层，文件后缀是否为 .json
动画空白或闪一下PNG 前缀、阶段、动作、编号；尤其是成年 jump_2
声音仍为原版WAV 路径、sound_event 与 nativeEvent、声音键和阶段是否对应
商店里找不到动物袋animal_shop、sack_hatch 和当前月份库存
产物没出现成年状态、饲料、心情、产物设备，以及掉落库与蛋物品的 ID
日志提示 ID 冲突给第二份模组分配新物种 ID 和动画机键，并同步改名

进一步定位时，查看 DTMAPI 日志中的模组 ID DTMAPI.AnimalPack 及 animals.definitions、animals.voices、audio 相关信息。

放到哪里多只动物怎么组织
animal_tbanimal.json、图鉴、特殊照料表在顶层数组里逐个追加动物条目，各自使用对应物种 ID。
item_tbitem.json、item_tbitemspawn.json追加各自的动物袋、产物和掉落库，物品与掉落库使用独立 ID。
mod_tbmodstoreextension.json同一商店保留一个 animal_shop 对象，把多个动物袋加入它的 extra_items。
animals.definitions每只动物追加一个定义，分别填写物种 ID、动画机键、PNG 前缀和帧清单。
animals.voices按物种与阶段绑定声音；本例四种动物共八条绑定。
audio.resources、audio.events集中登记包内声音资源与声音键；本例各八条。
