综合案例：音效、音乐与磁带

2026年10月28日 Yuuka

给小镇换一副耳机。开纸箱来句曼波，种田时听首新歌，再把喜欢的曲子装进磁带。音频负责唱，JSON 负责安排出场。

一、整体说明

本页面向熟悉官方内容 Mod 的作者，使用当前“抽象音效包”和“东方同人曲包”的实际配置。两个示例各自成包，可任选一条路线，也可把音效与音乐放进同一个包。

准备用途
DTMAPI 0.7.5 及以上提供内置音频模块，内容包启用后按需加载
音频文件WAV、MP3、FLAC、AAC（.aac / .m4a）均可
根目录 info.json、manifest.json登记模组信息和包身份
PackData/content.json登记音频资源与事件，DTMAPI 专属
Content 下的官方 JSON添加环境曲池、播放器曲目、磁带和商品，按用途选用
icon.png、preview.png模组图标与预览图

每块 JSON 都是一个完整文件，按代码框上方路径保存。旁注只解释字段和值；点击“复制 JSON”会取得完整纯 JSON。标黄处是音频路径、事件名和身份引用等常改位置，改名时把相互引用的地方一起改好。

曲目形式与音频文件

想做什么配置方式示例
替换操作音效effect + replaceNativeEvent + 对应音量分类纸箱、采收、挖矿、砍树、鱼钩入水
替换已有音乐music + route: Music + replaceNativeEvent目标填已有的 PLAY_BGM_* 事件，沿用原来的播放场合
加入环境曲池music + nativeEvent；在 sound_tbbgmgroup.json 引用东方三曲加入 farm_1
加入播放器与磁带music + nativeEvent；配置 CD 表、磁带物品与获取方式默认解锁或使用自己的磁带解锁

同一首歌可以同时加入环境曲池和播放器。只供播放器时，保留曲目与磁带配置，省略环境曲池文件即可；“八云紫主题曲”采用这条路线。

文件形式有两种：直接放源音频，或提前生成 .bnk Bank 与配套媒体。源文件由 Runtime 准备，预制文件由工具提前准备；两条路线使用同一套播放声明。长曲目推荐 stream: true，短音效按普通资源加载。

二、文件结构与加载规则

两个示例采用相同的包根布局，目录名可自定。Content/ 放官方数据，PackData/ 放 DTMAPI 声明与音频。

抽象音效包/
├─ info.json
├─ manifest.json
├─ icon.png、preview.png
└─ PackData/
   ├─ content.json
   └─ assets/
      ├─ manbo.wav
      ├─ waibi_babu_grass.wav
      ├─ what_the_dog_doin_mining.wav
      ├─ hachimi_tree.wav
      └─ gugu_gaga_fishing.wav

东方同人曲包/
├─ info.json
├─ manifest.json
├─ icon.png、preview.png
├─ Content/
│  ├─ sound_tbbgmgroup.json
│  ├─ sound_tbcd.json
│  ├─ item_tbitem.json
│  └─ mod_tbmodstoreextension.json
└─ PackData/
   ├─ content.json
   └─ audio/
      ├─ candidate-badapple.wav
      ├─ pool-iroha.wav
      └─ pool-tsuki.wav

放入官方本地 MODS 或通过工坊订阅，在游戏的 Mod 列表启用。内置音频模块由内容自动启用，清单按下文填写。所有 path 都相对整个包根，例如 PackData/audio/pool-iroha.wav。文件名可以自定，声明与实际文件保持一致。

加载、追加与冲突

  • resources[].key 为资源名，events[].key 为声音事件名，各自在本包对应列表内保持唯一。resource 引用资源名；nativeEvent 与官方表中的事件名逐字对应。资源和事件 key 建议用小写，新增音乐事件使用独特的作者前缀；所有引用保持大小写一致。
  • 本页用 replaceNativeEvent 替换现有事件，用 nativeEvent 接入新音乐，两项互斥。多个包替换同一目标时，按官方加载顺序由后者生效；同包重复目标取后声明。
  • 音效替换按原生事件覆盖所有调用位置。原生准入通过且替换资源就绪后播放新声音；音效尚未就绪或播放失败时使用原声。
  • 流式音乐在原生选中这首歌时准备，当前播放请求等待资源就绪；曲目结束和下一首选择由游戏处理。音乐声明使用 use: "music"、route: "Music"，省略 loop 与 minimumIntervalMs。
  • DTMAPI 默认开启 BGM 追加：相同曲池 ID 的 event_list 按加载顺序合并并去重；曲间间隔、切入与切出延迟使用后加载的那一行。关闭追加后，相同 ID 按官方规则整行覆盖。
  • 改动官方 Content、模组启停或 BGM 追加设置后，重启游戏查看结果。只调整音量时修改 volumeDb，保留原音频文件即可。

环境曲池按场景、月份、天气和时段选歌。播放器按曲目解锁记录选歌。加入曲池后，尚未解锁磁带的歌也能在对应环境中响起。

三、操作音效：抽象音效包

这个示例使用 5 段 WAV 和 3 份 JSON，直接替换常见操作音效。素材照着示例放好，纸箱就会自己报幕。

声音事件主要触发同事件覆盖范围
PLAY_RESOURCE_PAPER_BOX开启野外纸箱开启声；纸箱破坏使用独立事件
PLAY_RESOURCE_HARVEST割草、采收部分植被、挤奶和取毛设备、厕所等
PLAY_RESOURCE_GATHER有效挖矿命中其他使用同事件的石质可破坏物
PLAY_RESOURCE_FELL有效砍击树桩、果树等共用用途
PLAY_FISHING_HOOK_SPLASH鱼钩首次入水沿用原生水花与垂钓流程

挖矿与砍树包含最终破坏一击。等级不足等情形由游戏选择各自的错误提示事件。

{
  "UniqueID": "Yuuka.DTMAPI.ManboCardboardAudio",
  "Type": "ContentPack",
  "MinimumDTMApiVersion": "0.7.5",

ManifestVersion: 2 选择当前清单格式，名称、作者、说明与模组版本由 info.json 提供。schemaVersion: 1 则是下方内容文件的格式号，两者各管各的文件。

3.Content/sound_tbbgmgroup.json

本例保留 farm_1 的两首原曲，加入三首新曲。原生播放列表随机选择池中曲目，曲间休息 48 秒。农场也要喘口气。

Content/sound_tbbgmgroup.json
[
  {
    "id": "farm_1",
    "event_list": [
      "PLAY_BGM_23",
      "PLAY_BGM_15",
      "DTMAPI_MUSIC_BAD_APPLE",
      "DTMAPI_MUSIC_IROHA",
      "DTMAPI_MUSIC_TSUKI"
    ],
    "idle_time": {
      "x": 48,
      "y": 48
    },
    "fade_in_delay": -1,
    "fade_out_delay": -1
  }
]

默认追加模式会保留该池已经加载的歌曲。想让新增曲目在别的月份或场景播放，就按下表增加对应 ID 的完整配置行。只做播放器曲目时，省略本文件。

五、曲目池范围与对照

游戏会按当前环境挑选一个曲池。先选对池，再把事件名放进 event_list，新歌才有合适的出场机会。下表覆盖当前原生 31 个曲池 ID；第 1～4 月对应游戏日历的月份。

六、音频预制工具

DTMAPI 音频准备工具把源音频提前制成游戏可播放的 Bank。直接使用源文件的包也能加载；想提前完成媒体准备时，使用配套的 DTMAPI.AudioPrepare.exe。工具可离线运行，输入格式与前文一致。

  1. 打开工具，选音频文件。
  2. 选用途：操作音效选“操作音效（Actor）”，界面音效选“界面音效（UI）”，环境音选“环境音（Ambience）”，歌曲选“音乐（Music）”。
  3. “输出到”选一个空文件夹。
  4. 音量先用“日常”，也可以直接填 dB 数值，然后点“生成”。
  5. 把输出的 PackData 里的声音文件复制进你的包，路径保持不变；content.json 里的 resources、events 合进包里的 PackData/content.json。key、bankEvent 和文件名照工具生成的写。
  6. 给事件加上 replaceNativeEvent（替换原版音效）或 nativeEvent（接入新音乐）。音乐还要按前文配好曲池或 CD、磁带。
工具输出目录/
└─ PackData/
   ├─ content.json          资源与事件声明
   └─ audio/
      ├─ audio_随机ID.bnk   预制 Bank
      └─ 数字ID.wem         流式音乐的配套媒体

预制资源的 kind 为 bank，path 指向 Bank，media 列出配套媒体，事件通过 bankEvent 播放。发布包携带 Bank 和必要媒体即可；原始音频留在自己的素材目录。

每次生成到一个新目录，再把条目合入自己的内容文件。多个声音合用一份 content.json，各自的资源名和事件名保持唯一。

音量与试听

volumeDb 使用分贝：0 保持素材电平，负数降低，正数提高，"-inf" 静音。工具保留整段素材，音量写入声明；后续调音量直接改 JSON。

工具用途安静日常热闹
Music−32 dB−29 dB−26 dB
Actor / Ambience−26 dB−23 dB−20 dB
UI−11 dB−8 dB−5 dB

这三个档位用于开始试听。素材本身的响度各有不同，先固定游戏的主音量与分类音量，再和原版声音交替听，逐步调整。示例中的负数配合的是示例素材；换歌后按自己的耳朵重新定值。

七、游戏内验证

  1. 启用自己的包与 DTMAPI，重启游戏；查看模组加载与资源准备状态。
  2. 音效包依次测试开纸箱、割草/采收、挖矿、砍树和抛竿入水，确认触发范围与音量。
  3. 曲池包在第 1 月、农场、白天晴/阴天气试听 farm_1。播放列表会随机选曲，并保留本例 48 秒曲间间隔。
  4. 打开电话亭工坊贸易部，确认三盘磁带各售 100。Bad Apple 默认可在播放器选择；使用另外两盘后，检查对应曲目解锁。
  5. 需要验证持久解锁时，完成一次原生保存再重新读档；临时试听可直接退出。
遇到的情况检查位置
音效继续播放原声替换事件名、资源路径与准备状态；确认实际动作使用这个原生事件
歌加入了池却暂时没响当前月份/环境/天气/时段，以及随机选曲与曲间间隔
播放器看不到曲目CD 表、default_unlock、磁带 function.cd_id
商店没有磁带商店ID、item_name、四个月份的生成设置
能看到曲名，播放时无声bgm_event 与 nativeEvent、音频路径、volumeDb 和游戏音乐音量
多个音乐包同时启用后范围变化官方加载顺序、BGM 追加设置和同 ID 曲池的后加载字段
