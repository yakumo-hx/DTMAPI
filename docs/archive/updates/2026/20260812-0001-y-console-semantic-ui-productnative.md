## Source Request

The user approved a full Y-console 1.1.0 redesign toward the stable semantic layout of the reference T console: native ten-category item navigation, exact MarkPoint teleport targets, fixed weather controls, searchable monster/animal catalogs, official infinite fuel content, responsive scaling, nine game languages and removal of recurring UI/reflection waste. The final correction maps 鹿神池塘 only to `林地深处-右端`; the 庞卡雕像 mark at `后山悬崖-奥兰多` is excluded. After the first local deployment, the user manually exercised 1.1.0 and reported four follow-ups: fuel copy overstated persistence beyond machine capacity; all weather slots were disabled and monster failure was opaque; animal creation was intermittent while hidden-product readiness worked; and the 1920×1080 UI was too large with non-square cards, oversized world controls and an overlapping catalog pager. A second player pass confirmed animal creation and its capacity guard, while reporting that monster creation still failed, the world/advanced controls remained too large and scroll-dependent, teleports should fit one page, and catalog icon/name composition still looked detached. The user requested implementation, necessary tests and local enablement. This authorizes only local `PreparedNotSubmitted` state; it does not authorize a Steam upload or change the Catalog release stop.

## Implemented result

- Product metadata is `1.1.0` with minimum Runtime `0.6.1`; the game-loaded assembly remains `netstandard2.0`, Author SDK compilation still targets compatibility `0.5.5`, and native policy remains `doloctown-24456188-debugconsole-v1`.
- Runtime translation selection now resolves explicit developer override or cached game locale through full locale, base locale and English fallback. Locale files are case-insensitive, corrupt/missing candidates fail through once-logged fallback, and the product-owned language config plus ModConfigMenu dependency were removed.
- The catalog is stable: ten native item categories, then searchable/paged Monster and Animal virtual categories. Monster/animal cards share pooled cells and left-one/right-ten input, while subtype is only searchable/detail metadata.
- ProductNative monster and animal paths call their native room hosts, validate returned entities and exact host/global counts, roll a partial batch back in reverse, and circuit-break further batch creation for the active save if rollback cannot restore the prior count. Monster invocation now constructs the interface's exact native `UnityEngine.Vector2` from `DolocAPI.AgentPosition.x/y`; it no longer passes a boxed `Vector3` into reflection. The candidate also compares the value-type `MonsterProto` by value and stable `Name` instead of applying `ReferenceEquals` to two boxed values. Animal placement and three state variants use native capacity, walkability, adulthood and dynamic `TbHusbandry` thresholds without a sidecar or save.
- Teleport uses one ordered registry of thirteen transport marks followed by nine landmarks, deduplicated and resolved only by exact `MarkPointId`. The corrected 鹿神池塘 target is only `林地深处-右端`; substring, coordinate, bed and `后山悬崖-奥兰多` fallbacks are absent. UI and CSV share the registry and surface translated fail-closed reasons.
- Weather uses one `WeatherPanelSnapshot` and the actual seven `TbWeather.Id` enum names: `SUNNY`, `CLOUDY`, `RAIN`, `THUNDERSTORM`, `WINDY`, `ACID_RAIN`, `SCORCH_SUN`. Missing native rows remain disabled in place; current and forecast badges may coexist and compact widths wrap without reordering or pagination.
- Weather and spawn failure paths now write the requested ID/count, failure code and detailed message to the action log. Player status prefers the specific message, preserves a result after pointer exit and distinguishes monster host, animal host, capacity/placement and rollback-circuit failures instead of collapsing them into an opaque unavailable state.
- `dtmapi_creative_generator` remains the save-stable ID but is now the ordinary coal-sprite `ItemFunction` “无限燃料” with finite `electric_energy=1000000000`. It is injected through the official `Content/item_tbitem.json` plus nine localization sidecars and has no Generator quick button. All nine player descriptions now state that a compatible machine accepts fuel only up to its own capacity; they no longer claim that the full input value remains stored in the machine.
- The UI now applies `Scale With Screen Size`, normalized safe-area anchors, three breakpoints, responsive 3–8 by 3–6 grids and 44-pixel minimum targets. At 1920×1080 the wide design surface is centered and capped at `1500×820` (78.1% of screen width and 75.9% of height); narrower layouts still use the safe-area tabs/scroll model. The wide world/advanced region has no ScrollRect: seven weather slots occupy one fixed row, all twenty-two exact teleports occupy a dense `4×6` grid, and advanced controls wrap below them on the same page. Catalog cards remain fixed `84×84` squares; their icons are centered in the upper card and their name/source/status labels use explicit internal rectangles instead of stretched anchors, while the catalog pager stays in the reserved bottom band above status. Catalog cells/listeners are pooled, stable catalogs/reflection/icon data are cached, region dirty flags limit refreshes, and layout is recomputed only for screen/safe-area/breakpoint/tab changes.
- `UpdateTicked` is subscribed only while UI/input drain or a movement lease needs work. Closed idle state does not create a Canvas, read catalogs or perform layout/reflection work; ISSUE-014 release suppression, text focus, two clean Escape frames, legacy Y fallback and owned EventSystem cleanup remain intact.
- Dead UI helpers and private quick-action entrypoints were removed, `modItemsOnly` became one source filter, duplicate product-language state and weather reads were removed, and the title now uses the product manifest version. Frozen backend/public compatibility entrypoints remain present.
