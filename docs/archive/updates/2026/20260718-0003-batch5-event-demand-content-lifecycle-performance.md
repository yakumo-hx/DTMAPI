## Decision

Batch 5 is verified on the bounded G0-G7 route. Its purpose and delivered boundary are to make existing capabilities demand-driven, change-driven, lifecycle-explicit, observable and provably silent when unused.

The frozen pre-implementation comparison confirmed that DTMAPI was a mixed-maturity platform rather than an analogue of one SMAPI version; the bullets below are that admission baseline, not a current defect list:

- install transactions, source authority, owner cleanup, player Doctor, bounded support packages, QA isolation, ABI gates, deterministic Author SDK and release contracts are mature strengths;
- event ownership/main-thread safeguards exist, but zero-listener pre-work gating, snapshot allocation and bounded queue semantics are incomplete;
- specialized content loaders and indexes exist, but there is no shared dirty-generation, invalidation, coalesced rebuild and live-native propagation contract;
- requester-aware services and owner-bound API facades are substantial, but explicit capability/session demand behind passive facades, capability/version negotiation and optional-integration governance are incomplete;
- all thirteen GameBridge feature hosts are still constructed eagerly, optional routes share a Harmony owner, and the scheduler/selected content paths retain zero-consumer recurring cost.

SMAPI is architecture reference only. No SMAPI or third-party Mod implementation may be copied into DTMAPI. Every API/domain change must retain the project safety clause:

> 先做本轮 API/domain 的 native owner 方法体审查；未找到 native owner 或状态持有者前，不得通过 mod 层补丁冒充 API 重做完成。
