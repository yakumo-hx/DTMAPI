## Known Facts And Rejected Hypotheses

- Known: official local MODS packaging, base Chinese localization, fish roe display, and base animal bell display were already successful and were not redone.
- Known: direct `DolocTown.exe` launch can produce the fatal instance popup, so final smoke verification must keep using Steam launch unless explicitly testing that failure mode.
- Known: `HomePageUiState` can be retained while title panels or later returned title state changes invalidate UI objects; title button mount/unmount must treat destroyed objects as absent.
- Known: Unity Input System and legacy input are not sufficient in every player/smoke context; the F6 chain needed a foreground-process-limited Win32 fallback.
- Known: OneAction resource completion must ask the game's native resource/tool validation before applying extra damage.
- Rejected: treating a missing `DolocTown.exe` plus missing DTMAPI startup log as a DTMAPI 30s startup regression.
- Rejected: marking shared ActionSpeed interaction hooks as gameplay-complete before testing each real behavior.

## Implementation

- Bumped DTMAPI and migrated package manifests/install version checks to 0.1.13.
- Made the title DTMAPI button lifecycle idempotent: destroyed UI objects no longer block remount, and active title context uses the current user-input state rather than a stale cached state.
- Added an external-input-safe F6 path through `ReflectedUnityInput`: Unity Input System, legacy input, and a foreground `GetAsyncKeyState` fallback.
- Added AutoFishing config/status text for Chinese experimental states and conflict visibility, while keeping full automation experimental.
- Added ActionSpeed planting config fields and shared `AgentStateInteract` / `AgentStateEat` hook points for interaction/eat animation experiments.
- Added `AgentControllerState.UseItemContinues(float dt)` smoke/runtime hook support so right-click continuous eat/drink and bottle-fill experiments scale the game's own use-item timer instead of directly calling item logic.
- Added native `ResourceFellData(resource,currentTool,hitPoint)` validation before OneAction applies final resource damage.
- Added experimental OneAction fuel/feeder fill after the native interaction callback: extra fill attempts use the game's own `CostSelf`, then `PowerGeneratorFuel.AddFuel` or `Feeder.AddFeeds`.
- Added `AutoExerciseOneActionFuelFeed` smoke coverage that creates/falls back to game equipment targets, drives `Equipment.DecoratedInteract`, runs the native `AgentStateInteract.OnExit` completion callback, and verifies item count plus fill/progress deltas.
- Added a OneAction wrong-tool negative matrix smoke path that invokes the game's real `ToolCollider.HandleTools` on rendered tree/ore/garbage/weeds resources with deliberately mismatched tools and requires unchanged health, no removal, and no DTMAPI completion delta.
- Updated the OneAction resource matching to use the game type hierarchy for tree/tree-trunk and weed/weed-small resources instead of exact type-name suffixes.
- Updated the OneAction config status text so the menu reports the verified tree/ore/garbage/weeds wrong-tool matrix and verified fuel/feed native consume/fill path while keeping vegetation/dandelion paths experimental/pending.
- Added smoke debug instant-save automation using native `DolocAPI.SaveGame` / `DolocAPI.LoadGame`, with room/position/time/result logs.
- Added startup segment logs around bootstrap, Harmony, runtime start, manifest scan, official MODS scan, workshop scan, icon load, content query index, and mod load.
- Added smoke script switches for title-button lifecycle, external F6, and instant-save verification; later hardened external-F6 smoke to retry foreground delivery and fail fast if no DTMAPI input log appears.
