# DTMAPI 0.5.0-alpha Release Hygiene Report

Date: 2026-06-11

Status: release-preparation record for the Developer Preview branch.

> Ownership-policy note (2026-07-13): this report preserves the old 0.5.0-alpha marker-removal behavior as historical evidence. [Update 20260713-0011](../updates/2026/20260713-0011-player-runtime-only-uninstall-ownership-p0.md) supersedes that policy with a Runtime-only player uninstaller and non-destructive legacy marker metadata.

## Release Position

DTMAPI `0.5.0-alpha` is prepared as a new Workshop release batch:

- New DTMAPI Runtime / Installer item.
- New DTMAPI feature mod items.
- No in-place overwrite of old DLK/SMAPI Workshop items.
- Player-facing mod text can say the selected mods are stable for normal play, while technical docs continue to mark the runtime as Developer Preview and GameBridge APIs as Experimental.

## Recommended Player Migration

The safest path is:

```text
uninstall old DolocTown SMAPI runtime
unsubscribe or disable old DLK mods
restart Steam and Doloc Town
install DTMAPI Runtime
subscribe to new DTMAPI mods
check DTMAPI Settings -> Status/Mods/Logs
```

This avoids mixed hook owners and stale code DLL state. It also avoids relying on old SMAPI uninstallers to clean local mod folders that they did not own.

## Old Content Handling

DTMAPI detects old SMAPI/DLK paths and records them in `install-state.json`. It does not delete Steam Workshop cache. Local old packages are either left in place for guidance or moved only through explicit legacy-migration backup paths.

Observed local state during dry run:

- Steam Workshop unsubscribe can remove the old mod from the in-game enabled list after Steam/game restart, but it does not guarantee that every manually copied or previously migrated local folder is gone.
- The local `MODS/DLK_*` folders are still detectable and should be treated as legacy local packages, not as active proof of Workshop subscription.
- Known old Workshop cache IDs can remain detectable on disk; the DTMAPI installer records them but never deletes Workshop content.
- The safest player-facing migration remains uninstall old SMAPI, unsubscribe/disable old DLK mods, restart Steam and game, install DTMAPI, subscribe to new DTMAPI mods, then check Manager Status/Logs.

## Install State Schema

`DTMAPI/install-state.json` is generated as UTF-8 no BOM JSON and records:

- `InstalledAt`
- `DTMAPIVersion`
- `BinaryVersion`
- `SourceRepoCommit`
- `GameDir`
- `PluginDir`
- `FilesInstalled`
- `BepInExDetectedBeforeInstall`
- `BepInExInstalledByDTMAPI`
- `BackupsCreated`
- `LegacyDetections`
- `LegacyModsMoved`
- `InstallScriptVersion`

The file intentionally avoids Steam account identifiers and other player-private information.

Release hygiene hardening 2 adds a `mod_infos.before.json` backup record to `BackupsCreated` before official-local enablement entries are written.

## Uninstall State Schema

`DTMAPI/uninstall-state-YYYYMMDD-HHMMSS.json` is generated during uninstall and records:

- `UninstalledAt`
- `DryRun`
- `GameDir`
- `BackupDir`
- `FilesPlanned`
- `FilesRemoved`
- `FilesBackedUp`
- `FilesSkipped`
- `KeepReports`
- `KeepConfigs`
- `KeepBackups`
- `RemoveBepInEx`
- `BepInExRemovalAllowed`
- `RemoveOfficialLocalPackagesRequested`
- `OfficialLocalPackagesDetected`
- `OfficialLocalPackagesRemoved`
- `ModInfosBackupPath`
- `ModInfosEntriesRemoved`
- `Errors`

Default uninstall keeps player Mods, Steam Workshop content, reports, configs, backups, and BepInEx core. `-RemoveBepInEx` only becomes active when `install-state.json` says DTMAPI installed BepInEx and the user explicitly opts in.

`-RemoveOfficialLocalPackages` is a separate opt-in. When requested, the uninstaller only backs up and removes official-local packages that contain the DTMAPI marker `Content/DTMAPI/dtmapi-package.json`, backs up `SAVE/mod_infos.json`, removes the matching `Local.<OfficialFolder>` entries, and writes the details to uninstall state. Without that switch, official-local packages are reported and kept.

## Hardening 2 Addendum

Date: 2026-06-12

This follow-up keeps the same release position but tightens the pre-release package and installer checks:

- Compact web audit-package self-audit now verifies that every evidence ID listed in `AUDIT-PACKAGE.md`, `VALIDATION-SUMMARY.md`, and `WEB-REPORT-NOTE.md` exists in the package and has `result.json`.
- Compact web package defaults use the release hygiene smoke IDs from 2026-06-12 plus focused hardening evidence `GAME-SMOKE/20260612-015402`, `GAME-SMOKE/20260612-015716`, and `GAME-SMOKE/20260612-015832`, and copy only compact evidence files, not report zips or screenshot-heavy evidence directories.
- `DiagnosticsService.ExportLogs()` includes `install-state.json` and `release-manifest.json` in report zips when they exist, and `dtmapi-summary.txt` reports install/release present/missing/read-error state plus version and legacy counts.
- `check-dtmapi-status.ps1` reports DTMAPI-owned official-local package count, legacy detections, install/report status, and next-step guidance.
- `install-to-game.ps1` backs up `mod_infos.json` before edits, refuses to overwrite unreadable JSON, uses temp-file replacement, and supports `-InstallPublishedModsOnly` vs `-InstallAllDevOfficialMods`.
- The Runtime Workshop installer path remains runtime-only because package payload installs set `SkipOfficialLocalMods`; the eight feature mods are separate Workshop items. Developer local installs default to all dev official-local packages unless `-InstallPublishedModsOnly` is requested.
- `uninstall-dtmapi.ps1 -RemoveOfficialLocalPackages` is the only path that removes DTMAPI-owned official-local packages, and only marker-owned packages are eligible.
