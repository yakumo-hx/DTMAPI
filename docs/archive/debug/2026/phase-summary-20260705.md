## Executive State

The debug history has three broad phases:

1. 2026-05-30 to 2026-05-31: smoke harness, Steam launch, DirectExe, input, and visible-UI proof were separated. The main achievement was preventing Codex from confusing pre-runtime Steam/client failures with DTMAPI runtime bugs.
2. 2026-06-03 to 2026-06-18: manual QA drove feature-level fixes across AnimalViewer, AutoFishing, ActionSpeed, Y console, Mine, MoreEquipmentSlots, installer scripts, and the now-retired SecondMotor route. Most items were smoke-verified, but several remain manual-polish or historical-only evidence.
3. 2026-06-20 to 2026-07-05: native Unity/Mono GC crash investigation became the dominant debug thread. Many DTMAPI-owned lifecycle risks were cleaned or instrumented, but `ISSUE-010` remains open; current evidence points at native LoadGame/save activation over a larger stable process/title root set, not a proven single DTMAPI-owned leak.

## Stage Conclusions

- Early debug debt was mostly classification debt: DirectExe vs Steam, process vs fatal popup, input delivery vs visible UI, and Steam pre-process delay vs DTMAPI startup cost. Those boundaries are now explicit.
- Mid-stage feature regressions often came from smoke evidence that proved an API/log path but not the exact user-visible behavior. The durable lesson is to preserve manual issue order and add screenshots/telemetry where visuals matter.
- The SecondMotor path is the clearest example where repeated fixes and smoke passes were still not enough. The correct project outcome was retirement, not another clone patch.
- Installer/package bugs were largely PowerShell host, offline dependency, and support-helper validation boundary problems. The current direction is local-first/offline-first, strict install chain, warning-only support tools.
- `ISSUE-010` is not solved. The project has added the right evidence rails, but the latest evidence says the root cause is either native LoadGame/save activation under a large stable root set or a trigger/amplifier around full SaveLoaded object snapshot/logging. The next action must stay diagnostic and comparable.

## Handoff Rules

- For runtime lifecycle, save/load, title return, UI roots, hook/event dispatch, mod loading, Workshop loading, installer scripts, or long-run crash work, read `docs/debug/INDEX.md`, this summary, the relevant `issues/ISSUE-*.md`, and the matching smoke-matrix rows before changing code.
- Do not cite historical SecondMotor evidence as current vehicle support.
- Do not cite 0.2.3 smoke rows as proof against 0.2.4+ manual regressions.
- Do not mark `ISSUE-010` solved without fresh crash/no-crash evidence that includes Unity crash reports when available and bounded lifecycle counters across the relevant long windows.
- Do not destroy unknown native Unity objects to chase GC crashes. Count and classify ownership first; only clean DTMAPI-owned stale roots with shortest-reproducer evidence.
- When a manual report says a feature is visually wrong, require screenshot or telemetry evidence, not only a log line.
