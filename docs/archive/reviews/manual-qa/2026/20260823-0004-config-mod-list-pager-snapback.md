## 1. 订阅较多时无法翻到第二页配置 Mod

### 原始反馈与截图转写

- 玩家反馈：“我订阅的 mod 很多，翻不到第二页进行配置，按 `>` 没反应。”
- 第一张反馈图中的 DTMAPI 设置窗口已经显示两页，但玩家点击下一页后列表不变。
- 第二张原图显示 DTMAPI `0.6.1` 的 Config 页：左栏有十四个可见配置 Mod；页码明确为 `1-14/16  第 1/2 页`。因此配置页注册、排序、计数与分页窗口计算均已生效，问题发生在下一页交互后的状态提交或重绘阶段。
- 页码和 `<`、`>` 控件挤在左栏标题右侧，并延伸到右侧当前 Mod 标题区域；截图中的当前配置标题与分页区域发生明显视觉重叠。

### 代码事实与确定性复现链

- `ReflectedTitleMenuSettingsUi` 每页显示 `14` 个配置 Mod。点击 `DTMAPI.Config.ListPager.Next` 时，回调把 `configListPageIndex` 从 `0` 设置为 `1` 并请求重绘。
- 下一次 `RenderConfig` 仍保留第一页中当前选中的 Mod。现有代码随后检查该选中项是否位于 `configListPageIndex=1`；因为不在，立即执行 `configListPageIndex = selectedIndex / 14`，又把页码写回 `0`。
- 因而按钮事件即使正常到达，也会在同一次可见重绘前被选中项跟随逻辑撤销。玩家看到的稳定结果就是“按 `>` 没反应”。这不是偶发输入丢失，而是任何超过十四个配置页且仍选中第一页项目时都会发生的确定性状态回弹。
- 不是每个订阅 Mod 都注册 DTMAPI 配置页。多数玩家配置页数量不超过十四，或没有尝试浏览第二页，因此不会进入这条路径；本次截图中的 `16` 个注册配置页首次直接暴露了它。

### 分辨率结论

- 分辨率不是页码回弹的主因。Canvas 已使用 `Scale With Screen Size`、`1920x1080` 参考分辨率和 `0.5` 宽高匹配；同一逻辑在不同分辨率下都会把第二页重新拉回第一页。
- 分辨率会放大可用性问题：通用分页按钮只有 `30x22` 逻辑单位，在 `1280x720` 的等比缩放下约为 `20x15` 物理像素，点击目标很小。
- 布局重叠也不是分辨率才产生。配置列表分页从 `x=172` 开始，标签和两个按钮延伸到约 `x=404`；右侧配置标题从 `x=326` 开始。两者在设计坐标中天然相交，低分辨率只会让文字和点击目标更难辨认。

### 为什么“以前修过”仍然漏出

- 2026-06-12 的 Update `20260612-0012` 首次加入配置列表分页，同时加入了“让当前选中项保持可见”的每次重绘跟随逻辑；两者组合形成了本次回弹。
- 当时标题配置烟测通过直接请求指定 Mod 的方式到达 Mine 和 MoreEquipmentSlots 页面，没有实际点击配置列表的下一页按钮。
- 2026-07-26 的 Manager/GMCM 验收实际点击了 Manager `Mods` 页的下一页、末页和上一页；该列表没有选中配置页的强制回页逻辑。它不能证明 `DTMAPI.Config.ListPager` 可交互。
- 因此旧记录证明分页窗口算法和 Manager 翻页，不证明本次配置 Mod 列表的“点击后状态持续”。

### 已排除或降级的假设

- 不是“分页数据没有生成”：截图已经显示 `16` 项、`2` 页。
- 不是仅由宽屏或低分辨率造成：状态回弹与像素尺寸无关。
- 没有证据表明 Unity EventSystem 整体失效：同一窗口内 Mod 行、保存和其他按钮可用；源码本身已给出无需输入丢失即可完整解释症状的确定性链。
- 控件重叠和过小是独立的可用性缺陷，会增加误点概率，但不能单独解释每次翻页后仍稳定显示第一页。

### 修正边界

- 把“外部打开/新会话应跟随选中 Mod”和“玩家显式浏览另一列表页”分成两种状态。只有新的 Config 请求、页面/会话进入或选中项请求变化才把列表带到选中项所在页；分页按钮触发的普通重绘必须保留目标页。
- 分页只浏览左侧目录，不应自动取消当前 Mod 的未保存配置，也不应仅因翻页就强制选择目标页第一项。玩家点击目标 Mod 后继续沿用现有取消旧页面 pending changes 的事务边界。
- 把配置列表分页放入左栏标题下方的独立导航行，完整留在左栏内；Mod 行整体下移并保持十四行容量，扩大前后页按钮，不再与右侧配置标题重叠。
- 不改变每页十四项、配置排序、配置值保存/取消语义、Manager 其他分页、公共 API、游戏存档或 Workshop 发布状态。

## 验收门

- 单元/状态：当前选中项在第一页时，显式从第 `1/2` 页切到第 `2/2` 页后，后续普通重绘仍保持第二页；新的外部配置请求仍能把目录带回目标 Mod 所在页；项目数量缩减时陈旧页码仍被安全夹紧。
- 静态布局：配置列表分页导航行完全位于左栏，不与 `x=326` 起始的右栏相交；前后页按钮的逻辑点击区域大于旧 `30x22`。
- 运行：以至少 `16` 个注册配置页打开 DTMAPI 设置，实际点击下一页看到 `15-16/16  第 2/2 页` 和末页 Mod，点击末页 Mod可进入配置，再点击上一页返回；`1920x1080` 与玩家较低分辨率至少完成一处实际截图/复验。
- 在上述运行证据或独立玩家复验前，Owning Update 保持 `implemented` 或 `in-progress`，不得把 ISSUE-027 标为 `verified`。
