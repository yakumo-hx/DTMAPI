## 1. 无限燃料实际受设备燃料容量上限约束

### 原始反馈与截图转写

- 用户确认“无限燃料”投入设备后只会填满该设备允许的燃料上限。
- 现有说明宣称“正常游玩中几乎不会耗尽”，容易被理解为单个物品把十亿能量完整保留在机器内。
- 本项没有要求改变物品 ID、图标、普通燃料语义或十亿 `electric_energy`。

### 代码事实与根因

- 官方内容记录仍是 `dtmapi_creative_generator`、煤炭图标和普通 `ItemFunction`；内容值是有限的 `1,000,000,000`。
- 机器接收燃料时会按自身容量处理可接受值。因此高热值能保证把兼容设备填满，但不能证明机器保存了物品记录中的完整十亿能量。
- 根因是玩家说明把“物品输入热值”误写成“设备内可持续容量”，不是官方内容注入或燃料类型失败。

### 修正边界

- 九个官方内容语言的说明统一改为：热值很高，但兼容设备最多补充到自身燃料容量上限，不突破设备容量。
- 保留现有 ID、名称、煤炭贴图、普通燃料属性和有限十亿能量；不恢复独立 Generator 按钮。

## 2. 天气全部禁用，怪物生成失败且没有可理解原因

### 原始反馈与截图转写

- 用户观察到天气修改被禁止。
- 用户点击怪物卡后只知道失败，不知道实际原因。
- 第一张截图右上方出现两个“不可给予”禁用文本；底部状态区几乎贴住屏幕边缘，无法稳定承担失败说明。

### 代码与运行证据

- 玩家会话成功加载本地官方 `DTMAPI_YKeyConsole 1.1.0`，宿主绑定和 Advanced 激活通过；会话中没有 `weather-set` 或 `spawn-monster` 成功动作行，也没有对应 Unity 异常。
- 当前 `WeatherPanelSnapshot` 把固定天气键写成字符串 `1..7`。当前游戏 `TbWeather.Id` 的运行类型是 `WeatherType`，其 `ToString()` 返回 `SUNNY`、`CLOUDY`、`RAIN`、`THUNDERSTORM`、`WINDY`、`ACID_RAIN`、`SCORCH_SUN`。因此七个真实表行全部无法命中 `1..7` 字典键，UI 在调用前就把七格判成不可用。
- 官方 `DolocAPI.Command_SetWeather(string, bool)` 本身仍是当前房间的原生入口，并接受上述枚举名；无需复制 `ClimateManager` 或天气补丁逻辑。
- 怪物目录中的 `MonsterProto` 是只读值类型。当前后置条件对从实体再次读取并装箱的 proto 与目录中的已装箱 proto 使用 `ReferenceEquals`；两个值相同的装箱值也必然不是同一对象引用，因而每次生成都被误判为后置条件失败并回滚。
- 失败分支只返回 `SpawnDebugResult`，没有像成功分支一样写动作诊断；UI 又优先显示内部 `FailureReason` 而不是更具体的 `Message`，鼠标移出还会清除刚显示的状态。因此日志和界面都不能告诉玩家是哪一项校验失败。

### 修正边界

- 七格固定目录使用上述七个原生枚举名，并维持“晴、多云、雨、雷雨、大风、酸雨、烈日”的顺序；仍调用官方两参数命令并校验 `LocalWeatherType`。
- 怪物 proto 以值相等及稳定 `Name` 校验，不再对值类型装箱使用引用相等；Host、Controller、管理器包含关系和精确数量校验继续保留。
- 每次天气、怪物和动物失败都记录动作、请求 ID/数量、失败码和详细原因。玩家状态优先显示可理解的详细原因，并保留失败码用于诊断。

## 3. 动物有时生成失败、有时成功；隐藏产物满值正常

### 原始反馈与截图转写

- 用户观察到动物卡有时生成失败、有时成功。
- 用户确认“成年且隐藏产物可采”状态正确。
- 第一张截图展示固定十二张动物卡；部分两行名称越出矮卡片的可视区域。

### 代码与运行证据

- 同一玩家会话记录了 `slime.child`、`slime.ready`、`goat.ready`、`goat.adult` 的成功原生批次；动物畜牧进度还实际达到 `蜂蜡 35/35`。这证明 `IAnimalHost.CreateAnimal`、成年切换和动态 `TbHusbandry` 满阈值路径均可工作。
- 现有日志没有任何动物失败动作行，因为容量不足、落点不足、创建回滚等 `Fail(...)` 返回都没有统一写动作诊断。现有证据不能把玩家看到的每次失败区分为房间容量、无完整落点、宿主不可用、后置条件失败或卡片点击被重叠 UI 截获。
- 卡片根节点当前为 `100x74`，内部名称/来源文本延伸到约 79 逻辑单位；行距只有 78。文字、下一行卡片和后创建的分页控件存在视觉/命中重叠风险。该缺陷可解释“点击有时没有得到期望动作或原因”，但不能据此否认真实容量/落点失败。

### 修正边界

- 不改已通过玩家观察的隐藏产物算法、生日和无自动保存边界。
- 统一记录每次动物尝试及完整失败原因；成功/失败状态不再在鼠标离开时被无条件清空。
- 卡片改为真正正方形并留足标签空间，分页与卡片行不重叠。原生容量和整批落点预检仍然 fail-closed，不以强行生成绕过原生限制。

## 4. 宽屏 UI 过大、格子变形、右侧按钮过大且目录分页截断内容

### 原始反馈与截图转写

- 用户要求整体恢复到当前显示面积约 `70%–80%` 的观感。
- 两张 `1920x1080` 截图中，面板只留约 24 像素安全边距，几乎覆盖整个画面。
- 物品格实际约为 `100x74`，不是正方形；图标和底部名称被压缩或截断。
- 右侧传送按钮约为 `224x72`，天气/高级操作也显得过高。
- 目录分页位于最后一行旁边/上方，第二张截图中与底部物品名称区域重叠，而不是固定在目录区域底部。

### 代码事实与根因

- `Scale With Screen Size` 已启用，但宽屏 panel 仍直接铺满扣除 24 逻辑单位边距后的完整 safe area；`1920x1080` 下等同接近全屏。
- 目录绑定硬编码 `112` 横向步距、`78` 纵向步距和 `100x74` 卡片；布局行数仍按同一 78 步距估算，无法为标签与分页保留独立空间。
- 分页 Y 坐标由 `filterTop - 30 - rows * 78 - 8` 推导，跟随最后一行而不是锚定目录底部；其对象又晚于格子创建，可能覆盖最后一行文本/命中区。
- 传送按钮固定最小高度 72，天气固定最小高度 64；这超过既定 44 物理像素可点击下限，且没有玩家提出的大按钮需求。

### 修正边界

- 宽屏下把面板居中限制在约 `1500x820` 逻辑设计面；低分辨率和窄安全区继续使用全屏标签/滚动布局，不牺牲 44 物理像素最小点击区。
- 卡片采用同宽同高的正方形尺寸和一致步距；页大小继续由实际列数乘行数产生。
- 目录分页固定在目录底部、状态行上方；布局计算为它预留空间，最后一行不得与分页或状态文本相交。
- 右侧天气、传送和高级按钮在保留 44 物理像素下限的前提下缩小；长语言仍换行/滚动，不靠缩小字体硬塞。

## 验收门

- 静态/单元：天气枚举名七槽顺序；怪物 boxed proto 值校验；九语言燃料说明一致；正方形格子、底部分页、宽屏面板上限与 44 物理像素下限。
- 产品候选：Author SDK、DebugConsole native trace、Runtime floor、retained ABI 和 Catalog/sidecar 检查通过。
- 玩家复验：七种天气至少各一次、怪物左一/右十、动物成功与可解释的容量/落点失败、`1920x1080` 实际截图无格子/分页重叠，且宽屏整体观感落在用户要求的约 70%–80%。
- 在独立玩家复验前，本 Review 不宣称修复完成，Owning Update 不提升为 `verified`。
