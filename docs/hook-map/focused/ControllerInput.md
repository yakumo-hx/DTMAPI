GameBridge owns `Native/ControllerButtonAdapter`; Bootstrap calls it through the existing frame snapshot/capture path. No new Update component, XInput driver or public device DTO. `Gamepad.current`, `InputDevice.added`, `Application.isFocused` and cached `ButtonControl.isPressed/wasPressedThisFrame/wasReleasedThisFrame` getters provide the internal digital snapshot. Device replacement and focus loss reset neutral. No-device sampling has no logging, collection construction or device enumeration loop.

The 14 supported named controls are face positions South/East/West/North, shoulders, stick presses, Start/Select and four D-pad directions. These names do not promise Xbox labels. Existing `JoystickButton0..19` stays Unity legacy raw numbering, separately captured when that backend works; it is never mapped onto Gamepad face positions. Generic HID layouts without Gamepad shape, axis bindings and analog triggers are unavailable. Unknown strings remain editable.

The adapter reads private `buttonActions`, constructs one `ButtonAction(Int32, Func<String>, Action)`, and recognizes the unique final native `UnityEngine.Application.Quit()` delegate by method identity, not text. Native `OnClick(Int32)` dispatches the list position, not ButtonAction.index; the adapter does not renumber foreign objects. Own action goes immediately before Quit, preserving Cancel/SelectLast semantics. Native render/BuildNavigation and existing layout repair own the rows and callbacks. Exact owned identity is deduplicated/withdrawn on refresh/unregister/shutdown, and its delegates are cleared. Missing/ambiguous/nonterminal Quit degrades once without reordering native or foreign actions. Bootstrap supplies the label and existing open-only title callback; no public menu API or native implementation is copied.

Local matching reverse capture is research-only; no native implementation is copied. [Unity Gamepad API](https://docs.unity3d.com/Packages/com.unity.inputsystem@1.4/api/UnityEngine.InputSystem.Gamepad.html) describes the named Gamepad layout; this is not physical-device validation.
