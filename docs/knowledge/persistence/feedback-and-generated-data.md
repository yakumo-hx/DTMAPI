# 历史玩家反馈与派生数据边界

这里合并历史事实，不定义当前测试门。当前执行规则由 [PROJECT](../../../PROJECT.md) 与 [产品验证流程](../../workflows/product-change-validation.md) 拥有；历史 Review 的命令、版本门和旧工作空间路径不构成本轮授权。

## 先保留用户编号，再分配责任

[20260606-0001](../../archive/reviews/manual-qa/2026/20260606-0001-equipment-animal-yconsole-mine-oil-review.md) 的五项反馈必须按原序理解：

1. MoreEquipmentSlots 的三个深色槽只是只读显示，缺交互/hover。用户要帽子与已知被动装备的装卸、恢复和属性效果，原生外观仍由原生槽拥有；原生类型过滤不能升级成所有第三方类型兼容承诺。
2. AnimalProduction 的沼泽兽饱食 `0/100` 与隐藏角 `30/120` 文本挤在心情区域；需要独立信息行。marker 命中不能证明布局可读。
3. Y 控制台的 5×5 网格底部留白；倍速 `0.5` 实际重置，用户要求删除它，不能擅自实现减速。
4. Mine 为纯电设备；去掉燃油/容量。无 Oil 配方为金属框架 15、引擎核心 10、钢 20、煤 100；有 Oil 为框架 10、核心 5、钢 20、油 10。配方 ID、解锁与启用组合须有对应证据，JSON 编辑不等于游戏生效。
5. Oil 的临时 ID `dtmapi_oil` 需要正式命名，且牵涉配方、掉落、索引、本地化与旧存档引用；原记录没有选定新名称。

这些是同一反馈里的 UI、原生 owner、内容引用三类工作，不应强行扩成每项同一完整测试矩阵。实现状态要看所属 Update，不以早期审查的“待实现”覆盖后续成果。

## Email Archive：减少重复值，保留真实交互与信任边界

[20260829-0001](../../archive/reviews/code/2026/20260829-0001-email-archive-online-pattern-redundancy-review.md) 涉及旧 DLK 工作空间和 Wiki 的历史交付审查；这里仅保留流程知识，不读取或搬入其源码。

可从角色名、奖励目标、类别等原值推导的字段，以及逐条手写搜索串，不必与原数据同时维护。空条件、默认 portrait 和回退同值联系人可缩减，但八个没有邮件的联系人是产品数据，不能按空列表删掉。原记录估算 payload 从 221,749 降到 128,289 bytes，属于估算，不是最终测量。

两个六文件目录当时已经很小；应先减数据/手工表/构建器之间的重复，再考虑目录重排。禁止把 dist 当源输入后才知道头像或奖励标题。可选字段变化必须同步修正固定字段顺序的 preview 解析；不因一次精简引入 Config、Trace、Schema、Manifest、客户端抓取器或 DOM diff 框架。

保留必要的载入失败回退、唯一 ID/标题约束、转义与受限富文本、既有角色和邮件选择状态、移动端与浏览器前后退。去掉 popstate 需要真的验证历史导航，不能只看静态页面；允许头像不等于允许任意 HTML。历史验收为 205 封唯一邮件、32 角色、8 类别、88 条件及导航/检索/移动回退，不升级成每次数据修正的全量默认门。

## 真实输入与数据生成不能由替代指标关闭

[20260831-0001](../../archive/reviews/manual-qa/2026/20260831-0001-email-archive-ime-composition-cancel.md) 的 IME 问题不是沙盒禁中文，也不是 input 节点被重建；明确代码路径是在组合输入时全量 render 并回写同一 input.value。先避开 composition，后续再缩减为防抖结果区更新；仅加防抖仍回写组合值不够。事件测试与直接填中文不能证明 Windows 候选框不闪退，历史最后仍等线上更新与真实手工确认。

9 月 3 日后续两项顺序为：①搜索输入反复渲染；②条件表重新生成。条件应从指定最新基线结构化监听/附加条件/发信动作推导再应用少量人工覆盖，不能从邮件 ID 文本引用或旧 Wiki 条件倒推。版本补发、动态模板、无 sender 引用要分类；未解析项只阻止该信获得自动条件，不阻断整个页面。

## 身份与发布范围的去重复

[扁平交付](../../archive/updates/2026/20260829-0001-email-archive-flat-sandbox-delivery.md) 将每封信一层 group/entry 改为 emails[]，两个六文件加载方案二选一。后来的 [沙盒验收](../../archive/updates/2026/20260830-0001-email-archive-wiki-unsaved-staging.md) 已实际采用管理员 Debug 零件，Entrance 片段降为备用，不能继续作为测试前提。源不变的 JS/CSS/移动端证据可复用；一次 Lua 联系人归并和头像输出修复不必重放全部设备。32→26 联系人来自六个伪联系人的精确归并，含混“无署名”不可当全局别名；头像 wikitext 进入 JSON 后不会再解析是明确渲染边界。

[20260831-0002](../../archive/updates/2026/20260831-0002-email-archive-ime-and-data-driven-links.md) 从真实数据发现 10 组 66 封重名，甚至有标题/寄件人/正文/附件全同的四对，所以永久锚点必须用源 ID。正文提示或序号可辅助人读，但不是身份；不维护硬编码标题/人物/ID 表。两处广泛转入的既有来源工具只改锚点参数，独立管理员增量包四文件，不为链接再载入整表或另造 Lua 模块。

## 生成器演变中的有效简化

[20260903-0001](../../updates/2026/20260903-0001-email-archive-search-and-condition-regeneration.md) 对组合输入用 160 ms debounce 和结果区更新，消除完整 render；自动条件为 122 图、18 seed、4 人工例外、61 留空。Chrome 禁止自动 file 导航是一项工具限制，原页面检查不是新本地候选视觉验收，不能混称通过。

[占位过滤](../../updates/2026/20260903-0002-email-archive-hidden-placeholder-filter.md) 只有同时满足编号兄弟、同寄件人/标题/正文、显式空附件、无图/Yarn/直接代码发信引用、且兄弟存在真实附件引用才隐藏。它得到八个 `_4/_5`、205→197，而保留 Doloc 六封；条件空本身不足以隐藏。用户后来已发布两份 Lua 并真实沙盒验证，不再挂“等待上传”。

[20260904-0001](../../updates/2026/20260904-0001-email-condition-snapshot-overrides.md) 又把自动结果从人工 Lua 拆出：generated 仅有 build、conditions、hidden；人工 override 是独立权威，生成器不读取或重写它。条件缺失/空/空白回退自动，字符串覆盖，false 强制清空；隐藏项由独立布尔表覆盖，false 可重新显示。Manual 保留联系人/头像/分类，不堆 confidence/trace/review 等审计字段。自动 140、人工 4、八隐藏与前一版数字应按阶段理解。该候选仅本地完成，仍需管理员发布与沙盒三态验收；不要将前一版 Lua 上线当本版快照已上线。
