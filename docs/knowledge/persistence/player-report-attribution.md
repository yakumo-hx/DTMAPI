# 玩家反馈的现场归因

本页保留 2026 年 8 月长反馈中的已证实机制、被后继推翻的假设和仍缺的现场，避免只读首段时继承旧归因。原始顺序、精确私有输入 hash 与逐轮证据仍归 [七项/十项反馈 Review](../../reviews/manual-qa/2026/20260808-0002-public-newgame-and-functional-mod-regressions.md)。本页不复制玩家存档、日志或个人路径，不代替现行 issue/产品契约。

## 反馈不能按截图或同名症状合并根因

七项汇总未证明来自同一玩家/会话，后继十项新增不能删去旧的工具转移条目。库存、对话呈现、任务邮件各有直接 native owner。没有直接 Hook 只能排除直接接管，不能绝对排除此前共享状态被间接破坏；但已经证明某一会话未加载 DTMAPI，也不能继续把那例归给 Runtime。

1. **NPC 缺候选与对话卡住。** 普通台词正常但没有选项，与第一次文字就不出现是不同分支。前者查候选节点与数组，后者可进入下面的 TextAnimator 机制；其他玩家的具体 NPC/节点/首异常仍缺。
2. **箱到背包、世界拾取和货架。** 原生先 mutation、后同步无隔离 callback 的半事务窗口真实存在；鼠标操作还可能把物品放在不可见 buffer，不能把看不见直接称为永久删除。箱/背包/鼠标 buffer 要在单次动作前后守恒。世界物品增加后移除前也有标题/成就 callback 窗口。货架 6/6 真满不会走世界 Take，需区分架槽满、箱内满及 UI 首帧 Confirm。其余原始报告仍缺可归责现场。
3. **旧城市邮件。** 正式路径需 wetland 主线完成、DAY_PASSED、邮件与澳柯玛候选，再由对话启动 ruinedcity；迁移邮件 ruinedcity_continue 不是新流程必发信。具体玩家已是 visited=1、候选消失、任务未启动，且 0.99 补救未完成而版本门已越过。隔离重放证明当前官方迁移会补发，但不能推断历史外部中断者。最小恢复只添加原生邮件，不能全局降低版本重放多组副作用；派生修复验收归 [修复 Update](../../archive/updates/2026/20260809-0001-ruined-city-player-save-repair.md)，玩家读信推进仍按该 owner。
4. **新档黑屏。** 一个玩家的精确会话只加载 Configuration Manager 与 DolocPlus 1.3.1，没有 DTMAPI。开场文字触发 TextAnimator 全局 Assembly.GetTypes，旧类型导致 ReflectionTypeLoadException，Yarn 不再前进；同机移除 BepInEx 对照通过，最小已知故障集合是旧 DolocPlus。另一个左上 DTMAPI 按钮残留是明确标题 UI 生命周期缺陷，但小按钮不是全屏黑幕 owner，不能混成同根。

## 保留推翻早期嫌疑的证据

大型木箱 `wood 999 + 6` 与背包 18 空位只证明触发前条件合法，不证明此前实际丢失。后继完整包只有 Bootstrap，没有支持 Mxx 实际参与的证据，Mxx 从该玩家首要候选撤下；纸箱/货架扩容并不 patch 世界大型木箱直接路径。连续六档的最大 -199 可由制作/燃料计数核销，剩余 -10 与内容料理相邻，仍不能当丢失实证。

8 月 12 日第二次回传最终把该次 -73 全部解释为两个木桶消耗 60、八次发电机消耗 8、五份料理在提交时预扣 5。六十一个木头还保存在另一箱。该实例已撤回“库存丢失”，不能继续要求为它修库存事务。新增的真实故障是锅子首次打开 `Synthesizer.BufferItemFilter` NRE：先建缓存，再读未解析食材 ItemInfo，失败留下空缓存，所以第二次打开成功。尚未取得精确菜肴 JSON/玩家 Magic Storage DLL，坏 ID 与提供包未定；A/B 顺序是取证策略，不是归责。后续若再报即时丢失，观测窗只做一次取出，不混制作/加柴/料理，且不保存。

DolocPlus 版本也要分开：1.3.1 有玩家运行证据，1.3.2 含同类签名缺失类型是高置信静态复现条件；1.4.0 已消除全局类型污染，只剩五组按功能触发的局部兼容缺口，不能继承旧版所有对话卡死结论。ExpandedEncyclopedia 1.0.0 曾有静态候选依据，用户后继已将它从该玩家群调查优先级排除，不能只抽早期段落重新把它列首嫌。来源同上，尤其后续完整包、8 月 12 日与最终版本更正段。
