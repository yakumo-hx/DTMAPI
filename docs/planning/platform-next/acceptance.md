# 平台能力产品验收规格

- Lifecycle: `accepted-design`
- Role: E01–E08 的场景、观察值和证据要求；实现顺序见[路线](roadmap.md)，工作切片见[任务卡](tasks.md)，实际结果见[状态队列](status.md)所链接的 implementation Update。
- Contracts: [总架构](../../architecture/platform-next.md)、[Runtime 契约](../../architecture/platform-runtime-contracts.md)、[当前 Public API](../../api/public-api-matrix.md)。

本文件规定怎样证明能力，没有宣布任何场景已通过。它不保存候选版本、hash、测试结果或发布状态，也不建立新的 receipt/checkpoint 系统。

E01–E08 是场景家族，任务只执行其声明范围内的子项；必要但未完成的项记录缺口和后续 owner，未触发的家族不另写逐项免测说明，也不能记通过。早期保存 prototype 只验证身份/提交事实，M2 UI/配置验证不等待后期实体。阶段集成按已承诺能力集合选取并完整执行所需子项，而不是机械要求每阶段跑全部 E01–E08。

## 结果与执行原则

“代码完成”表示实现和该切片的源代码测试完成；“能力成立”要求对应作者旅程、真实宿主行为及故障出口有证据；“已发布”还需要精确发行产物、兼容声明和授权发布结果。三者分开记录。一个 helper 能编译、单元测试通过或 package marker 合法，都不能直接证明作者可以长期依赖它。

每次验收在既有 Update 记录实际 Runtime/SDK 包、API target、Mod 产物、游戏build、系统/Mono、官方来源及测试模式，引用Catalog、SDK target和包检查来源。旧运行可说明覆盖范围，不能拼成未实际运行的完整旅程PASS。

结果使用现有 passed、failed、blocked、partial 语义，注明未运行。`skip`、无法执行、源码检查或未到达目标行为都不是通过。不在产品承诺中的项目须在复盘和作者材料明确收窄，不能删掉测试后称全部成熟。

外部工程必须在仓库之外，仅用分发SDK、公开文档和合法本机游戏引用；不得有仓库ProjectReference、friend assembly、私有源码或paused-command bypass。使用公开CLI/IDE、官方Local与正常启动链。独立执行者可按文档重做；没有真实作者反馈时不声称人类可用性已验收。

纯.NET fixture使用[受管session](../../debug/protocols/test-artifact-retention.md)。触及共享游戏、官方MODS、启用状态或启动前取得runtime lock，完成后同工作区释放。路径取自设置/脚本，测试helper不偷偷安装或修复失败。

存档模式、未保存证明、专用可处置槽、隔离触发和恢复规则统一沿 [PROJECT规范](../../../PROJECT.md#codex-游戏测试规则)，不在本规格重定义。E05 保存中断/故障窗口仍使用其对应隔离 fixture；普通未保存或用户明确授权的专用槽验收不因此追加隔离。验证范围与复用沿[产品验证流程](../../workflows/product-change-validation.md)。

## E01：第三方作者完整开发回路（M1）

0.7.0 首次公开 SDK 执行 [PN-041 B01–B12](execution-sdk-msbuild.md#070-必需验收矩阵)，作为 E01/E02/E04/E08 组合：标准语义反例、实际 IDE、生成器、ref/lib、完整离线工具链、实际内部工程转换和最终 Mono。旧 SDK 未发布，不要求通用迁移器/旧客户端矩阵；内部 r5 PASS 不能代替新产物。

0.7.0 现有 Mod/接入执行 [PN-042 C01–C10](execution-compatibility.md#pn-042c准确最终候选与现有入口验收)，与 B 共用准确候选/完整 Release/游戏组合。原包、仍支持 API 的 consumer/implementer、官方来源/内容/外插件和安装恢复须按真实范围证明；第一方临时 CSV 已授权删除，精确允许集合保留，不恢复。后续 E05–E07 先方法比较再完整验收，实际数据/隔离承诺不减。

**参与者与输入。** 一个仓库外 Strict 作者工程、受测 SDK 发行候选、CLI 与 IDE/MSBuild 两条公开构建路径、当前可用 API target、正式 Local 安装工具、实际 Runtime 候选。作者只拿到计划对外分发的文件与说明。

**旅程。** 空目录create，CLI与公开工程构建产物，比较资源、manifest、闭包、符号和target。Mod注册事件、读配置并输出独特日志，check/package/install-local；官方启用、Steam启动，证明实际DLL/来源一致。制造错误按E02定位，修改/update，核对磁盘/进程状态和重启要求，重启看到新行为。withdraw后再启动不加载，按契约保留用户数据。

| 故障输入 | 必需观察 |
| --- | --- |
| 缺 SDK、未知/未就绪 target、非法依赖 | 构建前给准确原因；不偷偷换 target 或读取本仓库 build 输出 |
| CLI 与 IDE 产物差异 | 能定位构建参数/包含规则；两条路径不得一条可用一条丢资源 |
| 注释/字符串/合法自定义类型含禁用库名称；真实禁用引用及间接依赖对照 | 前者不被 SDK160 文本误拒，后者由实际引用/语义/闭包判定拒绝；保留 Runtime/Doctor 防线 |
| 配置含反斜杠结尾字符串、引号、逗号/冒号/嵌套；坏 JSON 的备份失败、读取权限/IO 失败 | 写后独立解析与原值一致；仅成功保全坏文件后才允许默认恢复，失败时原始字节不被覆盖；不把合法字符串改写或 IO 失败当作坏 JSON |
| 安装目录已有未知文件、错误 owner、路径冲突 | 拒绝覆盖或给明确恢复路线；不接管未知文件 |
| update 过程中注入失败/中断 | 恢复工具从受管 journal 得到确定旧/新状态，无半包可加载 |
| 游戏运行时改 DLL | 按冷更新政策拒绝变更或明确处理边界，不把磁盘完成称运行已更新 |
| 官方未启用、同 ID 多来源、候选已撤回 | 工具与 Runtime 解释实际选择原因，不自行启用或假称加载 |

**出口。** create到withdraw完整可复做，错误可定位，更新保留配置/约定数据且不删外来文件。不能手动复制DLL或调用内部入口补齐公开流程。

**运行层与证据。** 磁盘事务用.NET；加载、修复和重启采用新代码须游戏Mono。候选/工具日志归Update，真实启动/退出归smoke，错误分类沿Doctor/SDK测试。

上述配置/校验负例可复用同一实现输入下的 focused 结果，不要求在每个工具链任务重复注入全部故障。M1 最后仍要使用固定候选实际贯通一次旅程；只有中途影响剩余行为的输入变化才补相应重跑，不机械追加全 Release。

## E02：Mono、旧 ABI、源行与调试能力（M1–M3）

**参与者与输入。** E01 工程、保留符号的正式部署候选、准确源码映射、一个冻结旧 target consumer DLL、一个冻结旧 helper implementer DLL，以及拟支持的编辑器/调试器。旧程序集从冻结 target 构建或取有来源的冻结 fixture，不用当前源码重新编译冒充旧二进制。

**分开记录四种结果。** ①符号是否实际进入构建/包/部署；②异常日志能否映射到正确源码文件和行；③调试器是否可连接实际游戏 Mono；④断点是否实际命中且能查看局部变量、逐步执行。存在 PDB 只证明第一项，符号可读不证明 attach，attach 成功不证明断点成立。

**旅程。** 在作者方法的固定行产生受控异常，再在另一个可重复事件回调设置断点。核对实际加载模块与符号、编辑器源码和候选一致，记录具体连接方式；尝试断点命中、查看参数/局部变量、单步、继续运行并干净退出。随后加载旧 consumer 和 implementer，真正调用 helper/events/registry/可选服务缺失分支；不以 MemberRef 扫描代替调用。

| 故障/变体 | 必需观察 |
| --- | --- |
| PDB 缺失、旧符号配新 DLL、PathMap/源码根变化 | 明确“符号缺失/不匹配/源码不可达”，不显示错误行冒充定位 |
| 宿主未开放 Mono 调试连接 | 调查真实启动能力、符号格式与工具限制，保留失败步骤和原因 |
| attach 后标题/读档/异常继续运行 | 记录暂停带来的变化；调试操作不使测试错误地超时或触发保存 |
| 旧 helper 实现者不实现可选服务 | 旧行为仍可调用；新 helper extension 按契约报告不可用，不崩溃 |
| 新 target 在不足的 Runtime 上 | 在加载前或正式能力检查处解释最低要求，不到 MissingMethod 才沉默失败 |

若官方宿主无法提供断点，R1可收窄为“日志+源行定位”并列后续项；必须先完成attach调查，记录失败/阻碍/不支持范围，不能据日志成功称成熟断点调试。调试启动须可复现、可恢复、不修改官方二进制，不成为隐含玩家前提。

**运行层与证据。** 静态检查/编译负例用.NET；ABI调用、源行、attach、断点必须Mono。Update分别保存模块/符号、日志/界面及缺项；游戏写smoke，支持范围回写作者材料/API矩阵。

## E03：生命周期、调度与 Owner 隔离（M1 事实；M2 功能）

**参与者与输入。** 两个独立 Mod：A 记录事件、排队任务和资源；B 制造事件/命令异常与拥塞。输入包括现行生命周期及新 context/scheduler 候选、两个身份明确的 save 会话、公开命令前端。两种身份不等于必须建立隔离游戏目录，测试模式沿 PROJECT。M1 只观察现有 API/原生事实，M2 才要求新服务。

**旅程。** 记录 Entry→GameLaunched→标题→读档→SaveLoaded→已证明的 WorldReady→场景变化→返回标题→另一档→退出，核对线程及 epoch。加入新游戏和加载失败。A 从工作线程 Post、NextTick、Delay，B 持续提交；主线程分别取消、关闭 Owner、切世界和返回标题。记录真实开始/终态和资源释放，验证一个失败 handler/command 不阻止另一 Mod 的后续回调。

| 故障矩阵 | 必需观察 |
| --- | --- |
| 多帧源回退、暂停/失焦、读档重建 frame driver | 同一个 native frame 不重复执行；没有 timer 线程调用作者/native |
| 无当前世界提交、换场景、旧epoch到期任务 | 换场景用LoadingWorld，保留SaveSessionEpoch、失效WorldEpoch；旧工作不落到另一档/场景 |
| 队满、单 Owner 洪泛、延迟项堆积、回调再入队 | 容量/公平/下一 drain 规则成立，无静默丢任务或无限同帧递归 |
| 取消与开始竞争、排队期限到期、回调执行很慢 | 每项一个终态；只取消未开始项；预算不伪装成强制中断已运行代码 |
| Entry 中部分注册后抛错、清理某一步抛错 | 平台 roots 清理/保留失败重试状态准确，无关 Owner 不被清除 |
| 按住输入跨标题/换档、旧 facade/资源 token 再使用 | 无旧按键边沿，失效 facade 按契约拒绝，清理幂等 |

**出口。** M1给事实/readiness依据，M2证明快照、线程、队列和取消一致。每档不重新Entry，进程服务跨标题保留，save/world资源不跨epoch。平台roots归零不证明DLL、作者静态字段或未知Hook卸载。

**运行层与证据。** race/容量/FIFO用.NET；native时序、帧源、跨档和资源释放须Mono。沿生命周期日志、Owner诊断、Hook/Smoke及Update，R1/R2引用，不再发通过凭证。

## E04：依赖共存、共享契约、原生作者与反射（M3）

本轮详细格式/矩阵由[包契约 P01–P07](../../architecture/platform-package-contracts.md)及[执行包](execution-next.md)规定。必须同时覆盖包中声明/实际 PE/SDK 编译引用/Mono 实际绑定；相同版本字符串不证明同字节。optional Mod 的降级不能掩盖消费者缺少 CLR contract DLL。

**参与者与输入。** 仓库外 provider A、consumer B、无关 control C；纯 managed shared contract DLL、private helper DLL；任意合法新 ID 的 Advanced 工程；旧 Strict/receipt Advanced/legacy 包控制组。全部使用公开 SDK 通道，Advanced 不靠维护者逐 ID 登记或伪造 receipt。

**旅程。** 独立构建 A/B，在同一实际 Mono 进程经准确 Type 取得 API并完成跨 Mod 调用。随后替换为冲突闭包与缺失依赖，观察 Entry 顺序和拒绝范围。Advanced 工程用本机游戏引用完成真实 Hook/owner 清理，不能分发官方 DLL。反射样例读取真实 Mono 的实例/静态非公开成员并执行准确签名方法；不同程序集具有同全名类型，不能互用缓存。

| 故障矩阵 | 必需观察 |
| --- | --- |
| 必需/可选依赖缺失、版本低、循环、排序约束 | 必需闭包拒绝；可选按契约降级；C 仍可运行，日志说明依赖链 |
| 相同 CLR identity 同 bytes / 不同 bytes | 同 bytes 共享；不同 bytes 在加载前拒绝受影响闭包，不能静默先到先得 |
| 同 simple name 不同版本、private DLL 碰撞 | 遵循 Mono 实验证明的策略；未证实隔离时明确拒绝，不承诺任意共存 |
| provider Entry失败/停用，consumer缓存 API | registry可用性、dependent关闭和消费者释放符合契约；直接对象不冒充可自动撤销代理 |
| 两个 Advanced 相邻 Hook owner，部分安装后失败 | 精确 owner 清理；不撤销另一个 owner；无法清理如实报告重启要求 |
| 原生引用不允许再分发、包内混入宿主 DLL | SDK/package/Doctor 一致拒绝；引用生成来自本机，不依赖维护者私有 stub |
| 反射重载、基类私有成员、未找到/歧义/不支持签名、Owner关闭 | .NET/Mono 结果和异常语义一致；不支持的泛型/ref/out等不误报可用；绑定对象释放 |

**出口。** 两作者不改平台源码即协作；新原生作者自助构建/安装/诊断，包无官方字节；冲突解释准确且不阻断C。冷DLL/未知Hook边界明确，反射精确签名在Mono工作。

**运行层与证据。** manifest/闭包/算法用.NET；CLR身份、共享Type、Hook、私有成员和重启必须Mono。来源/结果归Update，已证明范围归API/Hook矩阵，R3据实际冲突冻结格式。

## E04.sdk：普通作者工程与真实依赖（0.7.0 审计增量）

**输入。** 从新交付 ZIP 解压的 SDK、准确 Runtime 候选、仓库外工程；对照外部审计的原 SDK r2，不能用仓库模板或手写回执补齐。实施细节见 [execution-sdk](execution-sdk.md)，规范化构建选项/资产见 AD-11/12，原生格式见 P08。

| 场景 | 能证明承诺的观察 |
| --- | --- |
| R01 普通类、普通/泛型委托、Newtonsoft.Json 13.0.3 | 恢复和离线重放接受合法托管元数据；真实 P/Invoke、Unmanaged、非合法委托的 Runtime 方法及其他不支持实现仍准确拒绝。实际托管委托库在游戏 Mono 调用成功；若 Json 与宿主驻留身份冲突，保留这项独立诊断和合法引用路线，不冒称任意双版本共存 |
| R02 Unity 泛型和非泛型对照 | `GetComponent<Transform>()`、普通非泛型重载及自定义 Component 类型参数，经公开 build/pack/Doctor/官方 Local，在 Mono 执行并得到预期组件；不能只看 compile 或 pack 成功 |
| R02 定义/实例/约束及旧格式 | 真实 TypeSpec/MethodSpec、泛型宿主、方法/类型参数、约束与精确成员漂移语料由 SDK/Doctor/Runtime 一致解释；无效包在 Entry 前归因，独立 Control 正常；旧 Native V1、既有准入格式和旧 target 保持原语义 |
| R03 常量和 XML | 条件编译真实改变可观察行为，XML 输出包含作者成员；同输入 CLI/IDE 产物一致，变化进入构建身份且不会误用旧输出。错误指出工程/属性/条件及可行修正 |
| R03 普通库 | 作者保留普通 SDK-style netstandard2.0 csproj，无 Mod 身份或 SDK 专用库描述；含传递库、资源和预生成源码的外部 DAG 能构建、打包、在 Mono 调用。每个库保留自己的编译选项，不继承主 Mod 的假定默认值 |
| R05.a 所选资产 | 真实多目标包中不相关资产不误拒，所选 netstandard2.0 编译/运行闭包明确；实际适用的 build/native/RID/generator 不静默丢弃；锁、离线恢复和身份冲突仍确定 |
| R05.b 后续扩宽 | 较低 TFM 的 BCL/facade 及新增运行资产升级需 R-Assets 真实 Mono；不同 ref/lib 已纳入 PN-041/B05 首发，不留在后续。旧 a 的 PASS 不覆盖任一新组合 |
| R04 准确 ZIP 的材料 | 从解压根目录追踪全部本地阅读链接；必需链可离线访问，源码专属参考明确标注。默认当前 target、显式旧 target 和 Advanced 示例（含实际必需参数）均照文档运行；库、泛型和新工程选项说明对应当前工具 |

负例必须证明执行了预期命令，并检查退出类别和具体诊断；usage、SDK999/internal error 或测试没到目标路径均不能代替 validation 负例。不同 SDK/Runtime 源码的旧 PASS 不覆盖新行为；未变化边界可按产品流程复用并由 Update 写清理由。

集中验收前先用现有 focus / `test.ps1 -Stage` 排错；最终完整 Release 是一次从头实际执行，不能拼接局部结果。本次计划没有补跑游戏；PN-038 的新 Runtime 读取/验证行为必须有新 Mono。旧标题长测只证明其准确场景，未变化的帧驱动/生命周期可有界复用，不能重标为新候选的一小时玩法通过。

## E05：存档事务与恢复（M4）

**参与者与输入。** 两个独立数据 owner，至少一个把 Mod 数据与实际 native 消耗/物品状态关联；隔离可丢 fixture、identity/commit 方案、候选 Data 服务、旧 SaveSaving consumer。原生保存责任函数、复制/删除/重用边界须先有 PN-024 实验证据。

先完成 V-Save / R4a 方法门。选择同档容器时必须证明无 Runtime 冷加载、对话初始化/进行和重存仍保留未知 owner 数据且无剧情副作用；随后容量、类型/命名碰撞和原生复制/备份回滚都须实测。选择侧车时独立 durable prepare、映射和同字节提交 witness 适用；不能让同档方案为不存在的外部日志补验。

**旅程。** NewGame 建立未提交 Working，执行消耗，经受测的真实官方保存入口保存，退出并独立冷启动读回；另轮修改后不保存返回标题，确认回到 Committed。改变保存入口时验证该入口；入口与提交路径未变时可复用既有证明，并按产品流程使用受控真实原生调用验证本次 Data 行为，不要求每次改动重复全部睡眠/自动保存入口。手动触发托管事件不能代替保存。对每个承诺支持的可注入失败窗口分别启动独立进程恢复并统计 native 与 Mod 数量、身份、事务和正式文件。

| 故障窗口/变体 | 必需观察 |
| --- | --- |
| prepare 前、候选写入中、已证明原生尚未提交就返回 false/异常 | 不提升正式玩法数据；失败可定位，下一次原生保存不重放已放弃操作 |
| 原生文件已替换，AfterSaveData 或外层 UI 抛错，未得到外层成功返回 | 分开 native 落盘与外层结果；同档载荷随实际档读回，侧车保留准确关联候选。独立 ParticipantCommitOutcome 仅适用有该阶段的后端；不重放 gameplay |
| 原生写入后进程中断、SaveSaved 通知前；侧车另有提升中断 | 以所选后端的真实提交证据恢复，物品/状态恰好一份；侧车不凭 slot/mtime 猜测，同档不靠内存结果覆盖已经提交的载荷 |
| SaveSaving连续失败后再次尝试 | 当前默认阈值0、不quarantine的正确边界保留；required participant 不因缺席被当作健康 |
| observer异常、必要数据准备异常 | 按新旧兼容设计区分；普通日志熔断不能跳过必要准备。required participant 独立协议只在选中后端确需时验证 |
| 同槽新游戏、删除、复制、改名、旧档恢复 | 不以slot/玩家名误绑数据；缺失关联时停止并解释，不猜测合并 |
| 损坏JSON、未来schema、旧版migration、磁盘无权限/不足 | 不覆盖唯一可恢复数据；故障范围隔离，迁移有明确结果与恢复路线 |
| Owner停用/不存在、orphan recovery、消耗/破坏后退出 | 管理恢复与GameplayMutation分开，不能借停用提交未保存变化 |

**出口。** 冷进程证明每个窗口的native与Mod提交对应，无丢失/重复/错档；待恢复不算通过，无法证明的提交不算成功。R4a明确格式、恢复及复制/云同步支持范围。

**运行层与证据。** codec/journal/迁移负例用.NET；native保存、冷启动及中断恢复须游戏。普通保存可按 PROJECT 使用已授权专用可处置槽；中断、故障窗口、跨档破坏及写入范围不明仍用隔离 fixture，不恢复玩家活档冒充通过。档案/sidecar 摘要、必要隔离/清理和日志归 smoke 与保存 Issue/Update。

## E06：内容修改、Host 与 Pack（M4）

**参与者与输入。** 两个仓库外作者的内容编辑 Mod、一个 Host、两个独立 Pack、一个正常官方原生内容 Mod和无关 control。选择一个真实原生数据表及一个图像领域，记录最终加载/合并/缓存接缝；不以现有内容索引当修改引擎。

R4b 先比较官方原生内容、薄适配和缺口所需的受限编辑，允许前两者满足作者目标。PN-025 的通用 Host 可先用只读输入/既有窄原生服务独立验证，不等 GameContent；这不代替内容编辑自身 E06。选中回调编辑才适用深层抛错矩阵，但不能将未经隔离的实现宣传成事务。

**旅程。** 首次启动按依赖加载 Host/Pack，实际读取修改后的表并显示图像；按所选方法调整官方启用顺序或受限编辑优先级，观察冲突解释。改变源文件后按已接受刷新契约重新读取、重开界面/场景或冷重启，分别观察新资源和原存活对象；只有宣称热刷新时必须验证对应 reload/invalidate。最后移除/禁用 Pack，经过规定刷新或重启回到正确状态。

| 故障矩阵 | 必需观察 |
| --- | --- |
| 同一asset双作者load/edit、相同priority、依赖顺序 | 结果确定，能指出贡献者和覆盖关系；不由扫描磁盘顺序决定 |
| 错路径/大小写/locale、路径越界、丢失资源 | 命名空间和规范化一致，错误归属正确，不读邻包私有文件 |
| 坏图像/坏JSON、编辑器抛错、部分批次失败 | 原生或上一有效generation回退符合契约，无半修改对象泄漏 |
| 编辑者修改嵌套集合/纹理后再抛错；原对象仍被其他消费者持有 | 证明所承诺格式的失败隔离；浅引用备份不算回滚。记录副本、解码、纹理 lease 和释放成本；无法安全隔离的格式只读或明确拒绝编辑 |
| Host缺失/版本低、Pack schema未知/重复ID | Pack 状态不可激活，受 Host 控制的 JSON/PNG 不被原生 Content 扫描提前生效或重复加载；实际画面/表验证。已有合法官方内容无须迁 Host |
| invalidate在world切换、Owner关闭、存活对象持旧句柄 | 旧资源释放/延期策略可观察；更新真的传播或明确要求重启 |
| 官方内容与两个Pack组合、移除后再读档 | 官方原生内容功能保留；无关control不被覆盖；持久部分同时满足E05 |

**出口。** 游戏行为/图像真的改变，不能只看索引；reload范围、生效时点、重启要求明确。诊断可解释双作者冲突，Host/Pack依赖、激活和失效完整。

**运行层与证据。** key/排序/schema用.NET；final merge、纹理句柄、存活对象与官方组合须游戏。NoNativeSave或E05持久fixture分开。Update、Hook/Smoke/API记录范围，R4b只冻结已证明家族。

## E07：领域实体、UI/输入/音频与组合（M5）

**参与者与输入。** 一个完整持久领域家族的 Host/Pack、第二个独立消费者、UI/输入/音频提供者、原生对照对象。选择真实有价值的家族；不要求一次覆盖所有动物、任务、机器和地图。

先按 V-Domain/UI/Entity 比较原生操作、现有菜单/控件和原生持久机制，再选择需新建的部分。原生已保存的实例不能在 sidecar 中重复保存/生成；通用 SaveData 只依额外载荷，所有持久方案仍要真保存/缺包恢复。UI 声明式树和领域通用事务没有先验完成要求，作者旅程及焦点/失败/清理语义仍必须成立。

**旅程。** 通过作者声明创建→游戏中定位/交互→消耗或生产→正常保存→退出→冷加载→升级schema；再测试缺失Host/Pack、恢复和删除。UI在标题、不同世界、两种典型分辨率、键鼠焦点/模态窗口间切换；音频以精确事件和scope区分原生/自定义对象，最后关闭Owner并退出。

| 故障矩阵 | 必需观察 |
| --- | --- |
| 重复实体ID、目标消失、句柄跨epoch、部分创建失败 | 稳定身份与临时句柄不混用，失败不留下半实体或错误补偿 |
| 背包满/低资源、consume与break、保存后重启 | native与Mod恰好一次关联，遵守E05而非只看DTO返回success |
| 缺Host/Pack或较新schema，随后重新安装 | 数据可识别地保留/恢复或有明确迁移；不无声删掉作者实体 |
| 两个UI/快捷键冲突、模态输入、拖动/关闭、resolution变化 | 焦点/抑制/释放有Owner归属，无原生菜单泄漏或看得到点不到 |
| 音频重放/中断、资源加载失败、切场景/关闭 | 不错替换原生对照对象；clip/texture/listener的释放可观察 |

**出口。** 完整旅程与两个消费者证明复用价值，政策留Host/Product。实际画面、互动/声音证明渲染/碰撞/可用性；日志或注册表存在不足。

**运行层与证据。** schema/ID/规则用.NET，其余须游戏；持久旅程按 PROJECT 选择专用槽或所需隔离，纯 UI 使用 NoNativeSave。领域 Update、smoke 及观察记录支持 R5，只冻结成立的子集。

## E07.input：现有配置菜单的绑定与方向导航

这是 PN-037 的独立产品子矩阵，不等待持久实体或通用 UI。分开记录：纯逻辑、真实游戏键盘/无设备、实体手柄/映射、玩家支持声明。源测试或虚拟输入不能填实体设备通过。

| 场景 | 必需观察 |
| --- | --- |
| 自定义按钮 | 录入、清除、多个替代绑定、恢复默认；AutoFishing 和配置入口分别按 scope 触发；一次按下只切换一次 |
| 配置事务 | 应用/取消/冷启保留；旧键盘串往返不变；未知设备绑定不被默默删除 |
| 菜单可达性 | 冷启动原生标题菜单，仅用方向/确认选到“Mod 配置”并打开；不能先用鼠标或 F8/F9。随后页列表/滚动/各控件/保存取消全程不用鼠标；焦点高亮、跳过隐藏/禁用项；关闭后可再从原生入口进入 |
| 导航和编辑 | 四方向/D-pad/摇杆按实际支持路径；长按重复、死区/抖动、滑块/数字/枚举/文本/重绑模式；返回先结束当前编辑 |
| 输入占用 | 捕获 Confirm 不同时激活控件，关闭不双 toggle，配置/暂停时不把动作泄漏到玩家移动/钓鱼；不能仅用 Core Suppress 证明 native 阻断 |
| neutral/设备变化 | 按住跨模态/失焦/场景，断开重连，切键鼠再切回；释放后才能重新触发，不补发过期边沿 |
| 外观与寿命 | 两种典型分辨率、长翻译/动态页、owner 停用/返回标题；焦点回退确定，捕获/订阅不残留 |
| 无设备 | unavailable 可读、不刷屏/忙轮询，键鼠与配置正常；无手柄并不让启动/菜单失败 |

已知本机没有手柄，可完成以上逻辑与键盘/无设备子集；E07 的设备部分保留 pending-player，不把“测试跳过”改成产品 PASS。实际系统按键注入和人手实体操作分别说明；已有标题打字框不能单独证明 Gameplay typing-focus。

公开实验描述分别列“控制器按键绑定”和“配置菜单方向导航”。正向玩家反馈需固定 Runtime/Mod/游戏版本、OS、型号/连接、Steam Input 路径和操作结果；核对 D09 完整旅程后仅晋级匹配范围。没有反馈、只有“没问题”而无可核对场景、模拟器/注入 PASS，都不能晋级全控制器正式支持。

## E08：升级、维护、兼容与性能（M6，过程持续积累）

首个 0.7.0 在 M3 之后执行 PN-031.a 的本家族子集；0.7 系列的 PN-033.a/b 准备弃用与预览，0.8 起 c 才物理清退。M6 标签不允许把发行/旧作者证明推迟到所有领域写完。公开版本范围和时序见[路线](roadmap.md#可发布版本)。

**参与者与输入。** 可重现的旧版发行包、候选新版、旧作者项目与旧二进制、不同支持游戏build/宿主的合法本地环境、固定标准Mod组合、可分享诊断包和离线文档。支持平台集合沿正式产品来源，不因测试机能运行就扩张承诺。

**升级旅程。** 外部作者从旧工具链打开工程，按文档迁移/构建，旧二进制先在新Runtime运行；安装升级、失败恢复、撤回/回滚，检查配置/数据。故意缺依赖、损坏包、游戏Hook签名变化，作者从Doctor与日志生成最小问题报告，另一执行者不读内部源码说明也能复现。受支持的破坏性迁移必须给可操作路径；未实现的自动更新不作为必需验收。

**兼容故障。** 覆盖新 SDK/不兼容 Runtime 的准确提示、旧/新 Mod 混用、可选 Hook 失配、Runtime 回滚、数据 schema 回退、离线依赖和报告敏感值。0.7.0 是首次 SDK 公开交付，不验收假定存在的旧公开 SDK 用户；以后实际发布两代 SDK 才增加相应升级组合。已部署状态恢复、数据保全和无关 Mod 存活仍必须成立。

**弃用与作者沉默。** 用保留的旧 consumer/implementer 二进制证明运行兼容，编译警告不能替代。至少一个作者不回复、使用量未知的旧包案例：说明替代面、行为差异、编译警告和按 owner/feature 去重的运行诊断；按 AD-09 留出已公告的最早版本与日期，预览移除能暴露失配并提供回退。未观测到调用不自动允许删除，缺少回复也不无限延期；内部删除与保留公共薄适配层分别判定。首次正式移除前才冻结具体窗口，不将研究示例当现行承诺。

**性能操作。** 固定机器、游戏build、分辨率/设置和输入路线，记录native-only、Runtime-only、0/5/25轻量Mod及一个真实代表组合。分别测冷/热启动、标题空闲、世界更新、资源刷新、换档、Owner关闭，采集启动耗时、update分布、分配/GC、retained roots、队列深度、原生资源及退出时间。至少三次可重复样本，报告全部样本和中位/尾部，不挑最好一次。

基线建立后，在实现Update先登记测量误差、增量预算及理由，再比较候选；超预算则修复或经复盘明确接受成本，不事后偷偷调阈值。硬件/build变化重建基线；分开观察空队列/零监听分配、scope关闭后的roots，不以总内存掩盖。

Runtime契约RT-03的队列保护值是实现初值，不是跨机器SLO。预算由设备/负载/体验实测确定。精确候选组合须连续至少一小时标题idle后读档、世界长测与循环换档，以覆盖已知GC风险；单次成功不保证任意Mod永不崩溃。

**出口与证据。** 旧作者升级和故障报告可复做；兼容/稳定/弃用/支持范围明确，成本有基线及解释，退出无进程。CI覆盖源码/包/ABI，游戏实验室覆盖Mono/原生，二者缺一不称整体成熟。Update及现有release/Doctor/API/Hook/Smoke/Issue保有证据，R6决定稳定承诺。

0.8 清退的额外对照：固定旧 DLL 确实引用被移除成员时，在执行前得到指明 API/替代或停止提供能力的诊断；只用仍受支持 0.5.5 子集的旧 Mod 继续正常运行；迁移后的新包实际 Mono 调用通过。接口/DTO 删除、provider 删除、内部实现删除和数据 reader 删除分别统计/判断。对外已公告的版本/日期未同时达到，不能把候选预览当正式清退；未回复作者的未知量沿 AD-09 处理。
